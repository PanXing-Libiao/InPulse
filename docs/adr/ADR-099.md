# ADR-099 SSO 按 Casdoor 群组类型过滤虚拟组

- 状态：Accepted
- 日期：2026-10-27
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-097](ADR-097.md) 的群组事实来源与 API 边界、[ADR-098](ADR-098.md) 的实体群组口径；沿用 ADR-032 的 SSO 安全边界、ADR-081 的组织成员模型，以及 ADR-023、ADR-029、ADR-031、ADR-075 的既有事务、错误与权限规则

## 1. 背景

Casdoor 同时支持 Physical 与 Virtual 两类群组。用户在 Casdoor 实体上只属于“测试部”一个 Physical 组，但 OIDC 的 groups claim 仍可能同时包含“测试部”和“Virtual Group3”。

ADR-098 只能按完整路径的父子关系收敛祖先，无法区分同一次 claim 中互不为祖先的 Physical 与 Virtual 组；group 路径本身也不携带类型。结果是 InPulse 仍把 Virtual 组当成真实组织成员，与 Casdoor 页面不一致。

用户要求只识别和展示 Casdoor 实体组；没有实体组的账号归入“未分类”。

## 2. 决策

### 2.1 群组类型来源与鉴权

- 不保留或使用本次用户 access_token。授权码交换仍只用于验证身份并取得 id_token。
- 对已验签、规范化和去重后非空的 groups claim，在数据库事务外逐组调用 Casdoor 的 `GET {issuer}/api/get-group?id=owner/name`。查询参数使用 claim 路径中的 owner 与末级 group name，不使用整条层级路径作为 group 主键。
- 请求使用与授权码交换相同的 Casdoor application `clientId` / `clientSecret` 作为 HTTP Basic 凭据：`Authorization: Basic base64(clientId:clientSecret)`。Casdoor 的 `AutoSigninFilter` 支持该 application 级认证；这是读取单个群组元数据所必需的受控调用，不是管理员账号或全量目录调用。
- application 凭据只用于查询本次已验签 claim 已引用的群组，不列取全量群组目录，不查询 claim 外群组，不缓存结果。
- `clientSecret` 只从既有 Secret 文件配置读取并进入本次服务端请求头，不进入数据库、审计、日志、浏览器 Cookie 或响应，也不写入任何新增存储。
- 群组元数据读取必须发生在数据库事务之外；数据库事务内只使用已得结果执行组织成员对账与 Session 签发。

### 2.2 严格校验与 fail closed

Casdoor 的 get-group 响应必须满足：

- HTTP 成功且 status 为 ok，data 是对象；
- data.owner 与 data.name 精确匹配 claim 路径解析出的 owner 与末级名称；
- data.type 只能是 Physical 或 Virtual；
- data.isEnabled 与 data.isTopGroup 是布尔值，data.parentId 是字符串；
- 顶层组的 isTopGroup 为 true 且 parentId 等于群组所属组织 ID（owner）；子组的 isTopGroup 为 false 且 parentId 等于 claim 路径中的直接父组名称；
- 顶层标记与 claim 路径深度一致。

网络错误、超时、非 2xx、非 JSON、status 失败、字段缺失、未知类型、路径或父级不匹配，一律归类为 group-metadata-failed。该分类下不得签发 Session，也不得创建或修改账号与组织；失败审计按既有尽力而为规则记录分类，不记录响应体、Secret 或路径明细。

groups 缺失仍表示未提供组织事实，不修改成员关系；groups: [] 仍直接清空成员关系。两种情况都不调用群组元数据接口。

### 2.3 实体组选择

- 只保留 type=Physical 且 isEnabled=true 的群组；Virtual 组与停用的 Physical 组都不写入用户直接组织成员关系。
- 过滤后的 Physical 组继续按 ADR-098 收敛同一路径族中只保留最深实体组；互不为祖先的多个 Physical 组仍全部保留。
- 已验签 groups claim 仍是成员关系集合的唯一真相。群组元数据只能缩小该集合，不能借 Casdoor API 返回值增加 claim 中不存在的群组。
- 过滤后为空数组时按已有的空 groups 语义清空全部组织成员关系，页面归入“未分类”，不创建 Virtual 组织或虚拟未分类组织行。
- 祖先 Physical 组仍可建立组织层级，但被更深实体组覆盖时不写用户直接成员关系。

### 2.4 外部配置与兼容

- Casdoor application 仍必须配置 JWT-Custom、Token fields 至少包含 Groups、Token group format 为 Path。
- 本次 SSO application 的同一组 clientId/clientSecret 必须能通过 Casdoor HTTP Basic 认证并读取 `GET /api/get-group`；若 Casdoor 返回 401、403、status 失败或字段不匹配，登录必须失败，不得回退到“全部 claim 都算实体组”或按名称猜测类型。
- 部署时必须确保 SSO application 与用户群组属于同一 Casdoor organization；不得使用跨组织管理凭据或将应用改为全量目录读取凭据。
- 不缓存群组元数据，避免同一进程内跨用户复用权限与陈旧类型。每个非空 groups 登录按 claim 逐项读取；空 claim 不产生请求。
- 生产启用前必须用真实 Casdoor 完成一次 Physical 与 Virtual 并存的登录 smoke test，并确认 Basic 凭据可读取 get-group、返回字段满足严格校验；桩 IdP 通过不能替代该验收。该验收已于 2026-10-27 在测试环境完成，见第 5 节。

### 2.5 安全边界

- issuer 必须是 HTTPS；SSO 请求继续使用固定超时与 `redirect: error`，不接受跨域重定向。
- Client Secret 只在服务端内存中组装 Basic 请求头，不写日志、不进入审计、不暴露给浏览器；不得把 Authorization 头或上游响应体写入错误信息。
- 本次不新增任何使用用户 access_token 或管理员 Session 的 Casdoor 调用。
- 不新增路由、OpenAPI、生成客户端、数据库迁移、权限矩阵条目或组织授权。

## 3. 影响

- Casdoor 页面只有一个 Physical 实体组时，即使 token 还返回 Virtual 组，InPulse 也只展示该 Physical 组织。
- 只有 Virtual 组或停用 Physical 组的账号会清空旧实体关系并归入“未分类”。
- SSO 登录新增最多与 claim 群组数量相同的 Casdoor 只读请求；任一元数据读取失败会让本次登录 fail closed。
- 已存在的错误 Virtual 成员关系会在下一次成功登录时按全量对账移除，无需数据迁移。

## 4. 放弃的方案

1. 使用本次用户 access_token 调用 get-group：其可用性取决于 Casdoor 版本与 API 权限策略，且会把登录新增步骤绑定到用户 token 生命周期；本次不采用。
2. 使用管理员凭据拉取全量组织目录：权限面过大，且违反最小读取边界。
3. 按名称包含 Virtual 或固定前缀猜测类型：Casdoor 允许任意 group name，会误伤真实部门。
4. 在元数据失败时回退到全部 claim 或默认 Physical：会把未知状态写入成员关系，破坏 fail closed。
5. 固定只取第一个或最后一个组：InPulse 不应猜测用户的 Casdoor 主组。

## 5. 验证

- API 单元：只保留启用的 Physical，过滤 Virtual 与停用组；查询使用 owner/name 与 application Basic 认证；顶层父级、HTTP、status、JSON、类型、路径和父级异常均被拒绝。
- API 集成（真实 PostgreSQL + 桩 IdP）：Physical 与 Virtual 并存时只写 Physical；从 Physical 切换为仅 Virtual 时清空成员并归入未分类；元数据失败不创建账号、组织或 Session；groups 缺失与空数组不调用群组元数据接口；群组查询发生在数据库事务之外。
- Web 单元：group-metadata-failed 显示统一认证群组类型读取失败提示，未知 sso_error 不回显原文。
- 真实 Casdoor smoke test（2026-10-27）：测试账号同时属于 Physical `libiaorobot.com/测试部` 与 Virtual `libiaorobot.com/Virtual Group3`；同一 SSO application 的 Basic 凭据可读取 get-group，返回字段通过严格校验。完成真实 SSO 后成员页只显示“测试部”，Virtual 组未出现，其余无实体组成员保持在“未分类”。
