# ADR-084：停用账号前的任务交接

- 状态：Accepted
- 决策日期：2026-10-19
- 接受依据：用户 2026-10-19 在停用账号弹窗 D 方案上明确选择「我决定好了用 d只要在 d 改就行」，要求停用账号时直接处理未完成任务，而不是先退出弹窗手工转派；同时要求多负责人任务默认保留其他负责人、唯一负责人任务必须选择接手人或删除，且接手人可多选。
- 关联：新增 1 条路由（125 → 126）；修订 [ADR-082](ADR-082.md) 的停用前置行为；沿用 [ADR-013](ADR-013.md)（单事务）、[ADR-019](ADR-019.md)（数据库级幂等）、[ADR-029](ADR-029.md)（契约响应与统一错误）、[ADR-031](ADR-031.md)（管理员门禁）、[ADR-040](ADR-040.md)（多负责人平权）、[ADR-058](ADR-058.md) 与 [ADR-059](ADR-059.md)（任务删除与审计/活动副作用）。

## 1. 背景

- 旧实现中，目标账号只要还有 TODO 任务，disableUser 就返回 409 ADMIN_USER_HAS_OPEN_TASKS，管理员必须先到各项目逐条改派或删除，再回到设置页停用。
- 任务散落在多个项目、模块与功能中，逐个查找成本高，也容易漏掉仅有该账号一个负责人的任务。
- 用户要求把交接直接放进停用弹窗：按项目展示未完成任务，默认保留多负责人任务的其他负责人；只有唯一负责人任务需要明确选择接手人（可多选）或删除任务。
- 停用仍必须保持原子性：交接失败时账号保持启用、Session 不被撤销，不能出现「部分任务已改派但账号没停用」或「账号已停用但仍有任务挂着」的中间状态。

## 2. 决策

### 2.1 交接清单读取

- 新增 GET /api/v1/admin/users/{userId}/offboarding，operationId = getAdminUserOffboarding，成功返回 200 AdminUserOffboardingResponse。
- 授权与 listAdminUsers 相同：仅当前有效的完整管理员 Session；只读接口不要求 CSRF、Idempotency-Key 或 If-Match，响应 no-store。
- 服务端只返回该账号当前仍是负责人、work_status = TODO、lifecycle_status = ACTIVE 且任务未删除的记录，按项目与任务编号稳定排序。
- 每个任务返回 projectId、moduleId、featureId、taskId、rowVersion、code、title、全部负责人；requiresHandover 仅在负责人数量为 1 时为 true。
- 每个项目同时返回当前 ACTIVE 的项目成员（排除待停用账号与已停用账号），供前端选择接手人；不返回登录名、邮箱等无关字段。

### 2.2 停用请求

- disableUser 从无 body 改为必填 AdminUserDisableRequest，幂等契约版本升级为 2.0.0。
- 请求体只列需要额外接手或删除的任务；未列出的多负责人任务由服务端自动摘掉待停用账号并保留其他负责人。
- 单个任务动作包含 projectId、moduleId、featureId、taskId、rowVersion、assigneeIds 与 delete：
  - assigneeIds 必须去重升序，且不得包含待停用账号；多负责人任务可额外增补多人。
  - 唯一负责人任务必须至少指定一名接手人，或 delete = true；两者都缺失返回 422 ADMIN_USER_OFFBOARDING_TASK_REQUIRED。
  - 只有唯一负责人任务允许 delete = true；多负责人任务仍需保留至少一名其他负责人，不通过删除规避改派。
- 服务端先锁用户行，再读交接清单并校验请求；任务按 taskId 升序处理，避免与其他命令形成相反锁序。
- 删除任务复用 TaskDeletionWorkflow，保留软删除、记录作废、聚合组校验、审计、活动与搜索投影等既有副作用；接手人改派复用 ProjectMemberTaskCommandPort。
- 全部任务处理后重新读取一次清单；若仍有未完成任务，返回 409 ADMIN_USER_OFFBOARDING_INCOMPLETE，整个事务回滚。
- 只有最终清单为空后，才递增 auth_version 与 row_version、写入 DISABLED / disabled_at、撤销全部 Session，并写 admin.user.disable 审计；审计 payload 增加 reassignedTaskIds 与 deletedTaskIds。

### 2.3 冲突与错误

- 用户不存在 404 ADMIN_USER_NOT_FOUND；目标已停用或状态冲突 409 ADMIN_USER_STATE_CONFLICT；If-Match 不符 409 ADMIN_USER_VERSION_CONFLICT。
- 任务已不在交接清单、scope 不匹配或 rowVersion 已变化时，分别返回明确的 offboarding 错误，前端提示重新打开弹窗刷新。
- 删除主任务时沿用 TASK_GROUP_MAIN_LOCKED，提示先解除合并；接手人不是项目活跃成员时沿用 TASK_ASSIGNEE_INVALID。
- 禁止停用自己、最后一名可用管理员保护、Session 撤销与审计规则保持不变。

### 2.4 前端停用弹窗

- 成员行与编辑用户弹窗的「停用」统一打开独立弹窗，标题为「停用账号 · 任务交接」。
- 顶部账号卡显示姓名、登录名、角色、状态与未完成任务数；无任务时直接显示完成态并允许停用。
- 有任务时按项目分组：项目名为主标题，项目编码和任务数放次级小字；唯一负责人任务用暖红色左侧色条并在项目标题标出「N 个必须处理」。含唯一负责人任务的项目排在最前，项目内唯一负责人任务也排在前面；其余项目与任务保持服务端的稳定顺序。
- 每个任务完整显示全部负责人姓名，不折叠、不显示「唯一」「+N 位」等额外标签。
- 每行只保留「＋ 添加成员」：默认不增补；点开后可勾选多名项目成员，选择结果显示为可移除的蓝色标签。
- 只有唯一负责人任务额外显示「删除任务」；删除后该行划线并显示「已标记删除 / 撤销」。
- 底部实时提示「还有 N 个仅该账号负责的任务未处理」，全部处理完才启用「确认停用」；提交时只发送真正有增补或删除动作的任务。
- 已按用户要求删除旧弹窗中的表头、四格汇总、「按项目交接」标题及冗余说明，也不恢复「处理方式」下拉。

## 3. 非目标

- 不把停用变成后台异步任务，不允许交接部分成功。
- 不改变任务负责人的多负责人平权规则，不自动猜测接手人，不自动创建项目成员。
- 不新增迁移；offboarding 是实时查询，不引入交接快照表。
- 不改变 deleteUser 墓碑化与 enableUser 的契约与前置条件；forceLogoutUser 已按 ADR-083 移除，本 ADR 不恢复。
- 不新增批量停用或跨账号交接。

## 4. 后果与验收

- 路由总数 125 → 126；permissions:check 为 126 条操作 / 126 条路由。
- API 单元测试覆盖 offboarding 读取权限、disableUser 请求体透传与 offboarding 错误映射。
- 真实 PostgreSQL 集成覆盖：唯一负责人未处理返回 422；多负责人任务默认保留其他人；唯一负责人任务增补多名接手人；唯一负责人任务标记删除；全部清理后账号 DISABLED、Session 撤销、审计含 reassignedTaskIds / deletedTaskIds。
- Web 单测覆盖无任务完成态、唯一负责人未处理时确认按钮禁用、添加接手人后可提交、只提交有动作的任务，以及请求头 If-Match / Idempotency-Key。
- Playwright 成员生命周期用例改为等待「全部项目已完成」后点击「确认停用」。
