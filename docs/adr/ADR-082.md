# ADR-082：离职账号墓碑化删除与成员状态筛选

- 状态：Accepted
- 决策日期：2026-10-19
- 接受依据：用户 2026-10-19 明确要求「要考虑后续员工离职，账户应该有个删除功能」，并确认成员页按「启用 / 已停用/离职」切换、默认显示启用、已停用/离职提供强制删除，历史业务记录中的账户名统一显示为「删除用户」，审计日志保持事件当时姓名；同时明确「强制退出先不改动」。
- 关联：新增迁移 `0047_user_deletion_tombstone.sql`；新增 1 条路由（125 → 126）；沿用 [ADR-013](ADR-013.md)（事务边界）、[ADR-019](ADR-019.md)（幂等默认）、[ADR-029](ADR-029.md)（响应校验与统一错误体）、[ADR-031](ADR-031.md)（管理员门禁）、[ADR-032](ADR-032.md)（SSO 身份映射）与 [ADR-081](ADR-081.md)（成员组织）。

## 1. 背景

- 员工离职后，账号需要从日常成员管理中撤出，但任务、迭代记录、项目动态、审计等历史数据仍会引用该用户。物理删除会让外键、审计溯源和项目历史失去主体。
- 仅停用会保留登录名、邮箱、姓名、头像和组织归属，既占用唯一登录名，也会让离职员工姓名长期出现在业务界面。
- 用户要求：成员页默认只看启用账号；已停用/离职账号单独筛选；在该筛选中可强制删除；删除后历史业务记录中的显示名改为「删除用户」，但审计日志不应看起来被回写。
- 用户同时要求本轮不改变「强制退出」的现有行为，因此 `forceLogoutUser` 的接口、界面与语义保持不变。

## 2. 决策

### 2.1 成员页筛选

- 「成员与角色」新增「启用 / 已停用/离职」筛选，默认「启用」。
- 「启用」只包含 `status = ACTIVE` 且 `deleted_at IS NULL` 的账号。
- 「已停用/离职」只包含 `status = DISABLED` 且 `deleted_at IS NULL` 的普通停用账号。
- 已删除的墓碑账号不进入任何成员筛选，也不出现在成员列表；服务端 `listAdminUsers` 不再返回墓碑账号，前端同时保留防御性过滤。
- 批量组织管理只在「启用」筛选出现；切换筛选会退出批量模式并清空选择，停用账号不参与组织批量归属。
- 「强制退出」按钮只对启用账号显示；停用账号不再显示该按钮，既有接口和撤销会话行为不变。

### 2.2 强制删除路由

- 新增 `POST /api/v1/admin/users/{userId}/delete`，`operationId = deleteUser`，成功返回 204 无 body。
- 授权为完整管理员 Session；要求同源、CSRF、`Idempotency-Key` 与 `If-Match`；数据库级幂等契约版本 1.0.0，重放策略为无 body。
- 前置条件：
  - 目标账号必须已 DISABLED，且尚未墓碑化；否则 409 `ADMIN_USER_STATE_CONFLICT`。
  - 目标账号不得是当前操作者本人；否则 409 `ADMIN_USER_SELF_MUTATION_REJECTED`。
  - 目标账号不得存在任何 ACTIVE 项目成员关系；否则 409 `ADMIN_USER_ACTIVE_PROJECT_MEMBERSHIP`，提示先转移组长身份并把账号移出全部项目。
  - `If-Match` 必须等于当前 `row_version`；否则 409 `ADMIN_USER_VERSION_CONFLICT`。
- 同一事务内完成：
  1. 锁定目标用户行并校验状态、版本与活跃项目成员关系；
  2. 复核当前管理员 Session；
  3. 墓碑化 `app.users`；
  4. 撤销目标账号全部 Session；
  5. 改写项目动态投影中属于该用户的姓名引用；
  6. 写不可省略的 `admin.user.delete` 审计。
- 墓碑字段固定为：`deleted_at` 非空、登录名改为 `deleted-user-{id}`、姓名「删除用户」、状态 DISABLED、`disabled_at` 非空、邮箱与头像与口令与组织归属清空、`is_admin = false`；同时递增 `auth_version` 与 `row_version`。
- 原登录名在墓碑化后释放，可由后续员工账号复用。`sso_subject` 保留，避免同一统一身份静默接管复用登录名的新账号；重新入职需另立 ADR。

### 2.3 数据库最终防线（迁移 0047）

- `app.users.deleted_at` 为可空时间戳；`users_deleted_state_check` 保证非空时全部墓碑字段满足上述固定值。
- `app.enforce_users_immutable_columns()` 继续保护 `id` / `created_at`；新增墓碑语义：
  - 只有从未删除切换到墓碑状态、且一次性写齐全部固定字段的更新才允许修改 `login_name` 或 `deleted_at`；
  - 已经是墓碑的行不可再被任何更新修改；
  - 不允许清除 `deleted_at`、恢复登录名或把墓碑账号重新启用。
- 迁移尾部部署断言校验列、约束、触发器函数与最终触发器同时存在。
- 账号不物理删除，保留主键供项目创建人、任务负责人、审计等历史外键继续引用。

### 2.4 历史显示名

- 任务列表与详情返回当前用户表中的 `creatorName` 与 `assigneeNames`；任务状态历史返回 `changedByName`。
- 正式记录详情在服务端按当前用户表补全 `authorName` 与 `handlerName`。
- 项目动态返回当前 `actorName`；动态摘要中包含该用户姓名的文本引用，在同一删除事务内改写为「删除用户」。
- 审计原始事件载荷、HMAC 哈希链与历史快照保持不可变。审计列表优先使用事件载荷中的历史姓名；`admin.user.delete` 使用 `before` 中的删除前姓名，原始快照仍同时保留 `before` / `after`，因此删除不会让旧审计行看起来被改名。
- `AdminUserItem` 新增 `deletedAt`；用户创建/编辑幂等契约升至 1.2.0，任务创建/编辑升至 4.0.0，`transitionTask` 升至 5.0.0，`completeTask` 升至 3.0.0。

### 2.5 认证与不可恢复性

- 登录、Session 签发、SSO 映射、启用、编辑、强制退出与再次删除均排除墓碑账号。旧 Session 在删除事务中全部撤销，后续请求返回 401。
- SSO 按 `sso_subject` 命中墓碑账号时只返回已停用映射，不先同步资料，避免触发用户不可变触发器并误报 500；登录编排按停用账号干净拒绝。
- 删除不可恢复；本 ADR 不提供还原、撤销或重新入职入口。
- 「强制退出」保持现有行为：仍只撤销 Session，不改变账号资料或删除状态；成员页仅对启用账号展示入口。

## 3. 非目标

- 不物理删除 `app.users`，不删除其历史业务记录、通知、动态、审计或索引行。
- 不批量删除成员，不按离职日期自动删除，不引入定时清理任务。
- 不修改审计原始 payload 或哈希链，不用墓碑姓名回写或替换审计列表中的历史姓名。
- 不改变 SSO 身份映射优先级、管理员高风险门禁、幂等摘要规则或「强制退出」的用户体验。
- 不在本轮处理重新入职后的 SSO 主体解绑；该能力需要独立 ADR。

## 4. 后果与验收

- 路由总数 125 → 126；`permissions:check` 为 126 条操作 / 126 条路由。
- 真实 PostgreSQL 集成覆盖：未停用 409、仍有活跃项目成员 409、移出后删除成功、墓碑字段、Session 撤销、活动摘要改写、任务姓名、审计、幂等重放、墓碑禁止操作、登录名复用与墓碑旧 Session 401。
- 数据库集成覆盖墓碑字段约束、不可再次修改、不可清除 `deleted_at`、不可改登录名及列/约束/函数/触发器存在性。
- Web 单测覆盖默认启用筛选、已停用/离职列表、墓碑在两个筛选均不出现、停用账号无强制退出按钮、离职页无批量管理、删除请求头与项目成员阻断文案，以及审计动作中文与删除前姓名展示；Playwright 覆盖编辑、停用、筛选、启用、强制退出、再次停用、强制删除与删除后列表消失。
- 强制退出的既有测试与行为保持不变。
