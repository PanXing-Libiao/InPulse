# ADR-109：移除功能层级，任务直接归属模块

- 状态：Accepted
- 决策日期：2026-10-30
- 接受依据：用户本次明确要求取消“项目 → 模块 → 功能 → 任务”中的功能层，层级改为“项目 → 模块 → 任务”，并同步移除与该层相关的能力。
- 替代范围：替代 [ADR-030](ADR-030.md) 中“任务可选功能 / 功能级与模块级任务 / 影响功能”的归属决策，替代 [ADR-045](ADR-045.md) 的功能状态与统计口径，替代 [ADR-096](ADR-096.md) 中功能删除范围，并修订 [ADR-022](ADR-022.md) 的 FEATURE 链接目标、[ADR-025](ADR-025.md) 的 FEATURE 搜索实体与 [ADR-104](ADR-104.md) 中“模块或功能共用能力项”的字段命名。历史 ADR 保留，不修改其当时结论。

## 背景

功能层同时承担长期档案、任务作用域、迭代记录归属、影响关系、外部链接目标、搜索实体、导入模板层级和权限能力分组。用户已明确要求以后不再使用该层，继续保留任何“隐藏功能”或“仅历史功能”的写入能力都会让任务归属、统计、搜索和权限继续分裂为两套语义。

## 决策

### 1. 固定层级

系统业务层级固定为：

```text
项目 → 模块 → 任务 → 迭代记录
```

1. 任务必须直接归属一个当前项目内的模块，不再有功能级 / 模块级两种 scope。
2. 迭代记录直接归属模块；绑定来源任务时仍通过 `task_id` 关联任务。
3. 模块统计不再返回功能数，只返回任务相关统计。
4. 功能层不再接受任何新建、编辑、查询、删除、导入、AI 辅助生成或搜索写入。

### 2. API 与前端收敛

1. 删除 `listFeatures`、`findSimilarFeatures`、`getFeature`、`createFeature`、`updateFeature`、`deleteFeature` 六条路由。
2. 删除旧的“功能内任务”路由族，仅保留模块任务路由：`/projects/{projectId}/modules/{moduleId}/tasks` 及其任务、状态历史、删除子路由。
3. 任务契约移除 `featureId`、`scopeType`、`impactFeatureIds`；独立迭代草稿移除功能范围与影响功能集合。
4. 项目 / 模块 / 聚合读、搜索、动态、通知与外部链接契约移除功能字段和功能目标。
5. 前端删除功能目录页与功能入口，模块卡和模块页直接进入模块任务。
6. 路由总数由 133 收敛为 119。OpenAPI 与生成客户端必须由生成工具重新生成。

### 3. 数据迁移

迁移 `0065_contract_remove_feature_layer.sql` 执行一次性扁平化：

1. 所有历史功能级任务保留原任务、负责人、状态历史、聚合组关系、迭代记录与链接，改为直接归属其原模块。
2. 所有历史功能级迭代记录保留记录、版本、遗留项与链接，改为模块级记录；来源任务关联保持不变。
3. 任务影响功能与记录影响功能关系退役；功能外部链接关联退役，`external_links` 主表保留供其他目标继续使用或追溯。
4. 功能搜索投影、功能业务表、功能编号序列和功能专用关联表删除。
5. 审计日志、项目动态、通知与历史身份/标题快照不删除；历史事件中的功能名称和 ID 只作为不可变历史展示，不再产生新的功能事件。

本迁移是破坏性拆除。发布时先完成数据库迁移，再同步发布 API 与 Web；旧版本写功能的路由不能与新 Schema 混跑。回退需使用迁移前备份，不允许把旧版本直接指向已迁移数据库。

### 4. 权限与删除

1. 权限列 `moduleFeatureEdit` / `moduleFeatureDelete` 改名为 `moduleEdit` / `moduleDelete`，三档取值和默认值不变。
2. 模块删除继续级联删除模块下任务、记录与全部下级，只保留审计、项目动态与删除事件。
3. 删除功能入口及其权限能力；不再提供功能删除或功能数据恢复。

### 5. 文档导入

固定文档模板移除功能段；模块下直接列任务。历史文档若仍包含功能段，预览返回明确的格式错误，不静默忽略。项目根级、指定模块的 AI 辅助目标不再包含 `featureId`。

## 影响

- 功能档案中的当前说明、验收标准、标签和历史功能名称不再作为独立业务实体保存；相关记录正文与审计快照仍保留可追溯文本。
- 依赖功能名称的列表、搜索、导入、概览和统计全部改为模块或任务口径。
- 历史功能活动仍可展示，但不是可导航的当前业务对象。

## 非目标

1. 不把功能自动转换为新的任务，也不猜测功能与既有任务的合并关系；历史任务按第 3 节直接上提模块。
2. 不恢复功能层、兼容旧功能 API 或保留隐藏功能写入路径。
3. 不改变项目、模块、任务、记录、聚合组、账号与通知的其他安全不变量。

## 验证

- 真实 PostgreSQL 覆盖迁移前功能级数据上提、功能对象删除、搜索投影清理、模块删除级联与新任务唯一归属。
- 契约检查覆盖 119 条路由、无功能 operationId / Schema / 搜索实体 / 外部链接目标。
- API 集成测试覆盖模块任务 CRUD、状态、删除、记录、导入、聚合读和权限配置新字段。
- Web 单测与 Playwright 覆盖模块直接进入任务、无功能入口、任务创建与搜索无功能字段。
