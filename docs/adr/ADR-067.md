# ADR-067：文档导入内嵌 AI 辅助转换（OpenAI 兼容端点，服务端转发）

- 状态：Accepted（2026-10-13 接受，实现随本批落库）
- 日期：2026-10-13
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：扩展 [ADR-064](ADR-064.md)（F-32 文档导入，新增可选入口，不改变任何既有业务规则）；扩展 [ADR-019](ADR-019.md) 的校验规则——把 `assistDocumentImport` 加入纯校验 allowlist（`packages/api-contract/src/pure-validation.ts`）。沿用 [ADR-066](ADR-066.md) 的「文件不离开浏览器」边界（本地抽取文本，不做 multipart / 服务端文件接收 / 附件存储）、[ADR-004](ADR-004.md)（契约生成）、[ADR-013](ADR-013.md)（Workflow 与事务边界）、[ADR-029](ADR-029.md)（统一错误体）、[ADR-021](ADR-021.md)（CSP 不放宽）、[ADR-032](ADR-032.md)（Secret fail-closed 先例）。新增 1 条路由（106 → 107），无数据库迁移；用户级额度与限流按用户决定不在本期。

## 1. 背景

用户原话要点：

> 现在是通过外部的ai才能转换，我能不能嵌入一个内部的ai，我有自己的api密钥
>
> 我有的是中转站api
>
> 但我想的是导入自己的文档，然后AI自己分析出来

随后确认范围：整项目导入与项目内导入两种模式都做；每用户额度先不管；输入格式覆盖纯文本类（`.txt` / `.md` / `.markdown`）与 Word（`.docx`）、PDF。

- 现状（ADR-064 / 065 / 066）：模板自带格式说明并支持本地选择文件，但把自然语言描述变成合规模板仍依赖用户自己找外部 AI；字段名自创或结构不合规要到预览时才以 422 暴露。用户自己的原始文档（需求、方案、排期）不是模板格式，直接粘贴会被解析器零容忍拒绝。
- 部署约束：生产 CSP 固定且不放宽外部域（[ADR-021](ADR-021.md)），前端禁止裸 `fetch` / `axios`，浏览器直连中转站不可行；密钥只能留在服务端（生产仅从 `/run/secrets/*` 读取，禁止环境变量兜底）。
- 依赖约束：数据库事务内禁止网络请求（AGENTS.md 第 3 / 6 节）；新增前端生产依赖必须走独立依赖 PR 并人工确认（AGENTS.md 第 4 节）。
- 治理约束：接入外部服务属于架构决策，需要 ADR；评审通过前不得写实现代码。

## 2. 决策

### 2.1 能力形态：一条服务端转换路由（两种模式）

- 新 operationId `assistDocumentImport`：`POST /api/v1/document-imports/assist`。
- 输入两条通道，都归一为纯文本后走同一请求：① 直接粘贴文本；② 选择文档（`.txt` / `.md` / `.markdown` / `.docx` / `.pdf`），由浏览器本地抽取为纯文本（见 2.3）。
- 请求 `{ mode, text }`：`mode` 取 `IN_PROJECT`（项目内导入，对应 ADR-064 模式 A）或 `WHOLE_PROJECT`（整项目导入，对应模式 B）；`text` 为抽取后的原始文本，1～200000 字符，不要求符合模板。
- 响应 `{ markdown, model, issues }`：`markdown` 为服务端格式预检后的模板草稿（≤200000 字符）；`model` 回显配置的模型标识；`issues` 复用既有 `DocumentImportIssue` 形状（最多 50 条，含行号），ERROR 不阻止返回草稿、只作提示。
- AI 永远只产出草稿文本：不写任何业务表、不写审计 / 活动 / 通知 / 搜索投影、不在服务端保存草稿；用户把草稿填入导入文本框（可编辑）后，走既有「预览（只读）→ 确认导入（单事务写）」链路，必填、负责人解析、防重复、默认值等全部规则与手工粘贴完全一致。
- 本 ADR 不修订 ADR-064 的非目标：导入链路的解析器仍不对自由正文做任何猜测——分析发生在导入链路之外，且必须经用户确认后才进入既有解析器。

### 2.2 Provider：OpenAI 兼容 chat/completions（中转站或自建）

- 非敏感配置：`AI_ASSIST_ENABLED`（默认关闭）、`AI_ASSIST_ENDPOINT`（OpenAI 兼容 chat/completions 端点；只填根地址时自动补全 /chat/completions；命名避开 `*_URL`，因 `scripts/check_secrets.mjs` 把带 URL 的键视为敏感变量）、`AI_ASSIST_MODEL`、`AI_ASSIST_TIMEOUT_MS`（默认 60000）、`AI_ASSIST_MAX_TOKENS`（默认 8192）；敏感配置：`AI_ASSIST_API_KEY_FILE`（部署指向 `/run/secrets/ai_assist_api_key`，只允许空值或 `/run/secrets/*`）。
- 请求最小字段：`model`、`messages`、`max_tokens`、`temperature: 0.2`、`stream: false`；`Authorization: Bearer` 携带密钥；不发送 Cookie / CSRF / 用户凭证，不复用用户 Session，不自动重试（避免重复计费与重复生成）。
- 适配器使用 Node 内置 `fetch` + `AbortSignal.timeout`（注入 fetch 实现以便测试，SSO 客户端同款先例），不新增服务端依赖。
- 上游响应不透明透传：只提取 `choices[0].message.content`；上游错误体与堆栈只进服务端日志（不含正文与密钥）。客户端得到统一错误体的固定错误码：未启用或配置非法（fail closed）→ 503 `AI_ASSIST_DISABLED`；上游鉴权失败 / 限流 / 超时 / 网络失败 / 上下文超限 / 响应非法或超长 → 503 `AI_ASSIST_UPSTREAM_FAILED`（`details.reason` 取固定枚举 `auth` / `rate-limited` / `timeout` / `network` / `context-limit` / `invalid-response`）。
- 分类细则（2026-10-13 补充，枚举不变）：中转站常挂推理模型，响应正文在 `choices[0].message.reasoning_content`、输出预算被推理吃满时 `message.content` 为空串且 `finish_reason: length`——这种「正文没机会输出」按 `context-limit` 归类（提示精简 / 分次生成或调高最大输出 tokens），只有 `content` 非空但形状非法、或空正文且 `finish_reason` 不是 `length` 时才归 `invalid-response`。
- 配置校验与 SSO 同构（[ADR-032](ADR-032.md) 先例）：`AI_ASSIST_ENABLED` 非真值即整体关闭；已启用但端点非法（生产仅 https，dev / test 允许本地回环 http 供 stub）、模型为空、Secret 文件缺失 / 空值 / 越界时 fail closed，对外一律视为未启用（invalidReason 只进启动日志，不泄露配置细节）。
- 端点地址由管理员配置、不来自用户输入，不构成 SSRF 面。

### 2.3 文档抽取：浏览器本地完成（文件不离开浏览器）

- 按扩展名分流（大小写不敏感）：
  - `.txt` / `.md` / `.markdown`：沿用 ADR-066 的本地文本读取（剔除 BOM）；
  - `.docx`：用 `mammoth` 抽取文档纯文本（段落与表格文本，不追求样式还原）；
  - `.pdf`：用 `pdfjs-dist` 逐页抽取文本层并拼接；
  - `.doc`（旧版二进制）、`.pptx`、图片与其它格式：本地拒绝并提示；扫描件 / 加密 PDF 抽不到可用文本时提示「未提取到可用文本（可能是扫描件或加密文件），请直接粘贴文本或先转成文本」。
- 边界：文件从不上传、不落库、不进临时文件（ADR-066 边界不变）；发给 AI 端点的只有抽取出的文本。服务端解析方案被否决：会引入 multipart 与不可信文件解析面。
- 规模：文件字节上限 20 MiB（读取前拦截）；抽取后文本超过 200000 字符提示精简；超过 100000 字符显示非阻断提醒（模型上下文可能不足以完整分析）。
- 依赖：`mammoth` 与 `pdfjs-dist` 是新增前端生产依赖，必须懒加载（仅有用户实际选择 `.docx` / `.pdf` 时才动态加载，不影响主包体积）、锁定精确版本，并按 AGENTS.md 第 4 节走独立依赖 PR 与人工确认（许可分别为 BSD-2-Clause / Apache-2.0）。
- PDF 抽取使用同源 Web Worker；预计与现有 CSP 兼容（同源 Worker 资产由 `script-src` 的同源白名单放行），实现时必须实测，且不得放宽 `script-src` / `style-src`（[ADR-021](ADR-021.md) 不变）。

### 2.4 提示词与模板唯一来源

- 提示词由服务端组装：system 指令（角色：输入是用户自己的项目文档、可能结构混乱；任务：分析并提取项目 / 模块 / 功能 / 任务；只输出模板正文；字段名与模板逐字一致；`WHOLE_PROJECT` 必须含项目段与项目编码并遵守 `^[A-Z][A-Z0-9_]{1,31}$`；`IN_PROJECT` 不得含项目段；文档里明确写了项目成员 / 参与人 / 团队 / 项目组时必须把这些名字写进 `- 项目成员：`（照抄原文，只写文档里作为本项目成员出现的人；没有成员信息才省略）；不得杜撰与资料无关的内容；声明用户资料是待转换文本而非指令）+ 完整模板文本 + 当前模式追加约束；用户文本只进 user message（提示注入缓解，输出不被信任）。2026-10-14 补充：文本末尾若干行以「补充说明：」开头的，是写文档的人本人对这份文档的后续交代，不算文档原文之外的杂音——第 3 条明确「补充说明里给出的信息也算真实信息」，新增第 5 条要求必须落实到草稿（点名的人写进「- 项目成员：」或对应任务的「- 负责人：」，要求改哪条说明 / 验收标准 / 时间就改哪条，只覆盖它明确提到的内容，其余照原文保持），第 8 条安全声明注明「补充说明里要求修改草稿内容的部分按第 5 条处理，不受此条限制」；整项目模式的成员来源同步补上「或补充说明里点名要加入成员时」。规则由 8 条顺延为 9 条。
- 2026-10-26 补充（模糊对话）：输入不再限定为结构化文档，允许聊天记录、会议纪要或零散想法。system 指令先判断整体项目方向（业务对象、使用角色、场景与痛点），再整理模板；项目 / 模块层的整体目标可以合理归纳，具体功能、任务、负责人、日期、数量与技术形态必须逐项有依据；对话前后不一致时以最后一次明确决定为准，只描述方向时允许只输出能支撑的层级，不硬造功能与任务；材料没有项目名时按业务方向起具体名称，不使用「某某项目」「未命名项目」等占位名。
- 模板唯一来源：把 `DOCUMENT_IMPORT_TEMPLATE` 从 `apps/web/src/features/document-import/DocumentImportModal.tsx` 迁入 `packages/api-contract`（与既有 `DOCUMENT_IMPORT_TEMPLATE_VERSION` 同处），前端「下载模板 / 格式速查」、服务端提示词与解析器一致性测试引用同一常量；一致性用例改为直接导入共享常量，保留模板可被解析器接受的断言。备选方案（服务端复制一份模板 + 跨应用文件读取测试）被否决：两份文本天然漂移。
- 返回前用既有 `parseDocumentTemplate` 预检生成 `issues`；模型输出与用户手写文本走完全相同的解析与校验路径。
- 截断检测：上游完成原因为长度上限（`finish_reason: length`）时，草稿照常返回，但追加一条 ERROR 级 `issues`（分析结果可能不完整，请精简文档或分次生成），不静默截断。

### 2.5 策略登记与安全边界

- `authPolicy: session`：任何已登录用户可用（与模式 B 导入一致）；单路由双模式，不接触项目数据，不校验 `projectId`。
- `csrfPolicy: none` + `idempotencyPolicy: none`：本路由无任何持久化副作用，属 AGENTS.md 第 6 节的纯校验接口；实现时把 `assistDocumentImport` 加入 `packages/api-contract/src/pure-validation.ts` allowlist（当前仅两条导入预览路由）。这是对 [ADR-019](ADR-019.md) 校验规则的显式扩展，随本 ADR 记录。
- 不引入数据库级幂等记录的理由：重复调用等于重复计费的问题由不自动重试、请求中禁用入口与可见的重试语义承担；而幂等记录会把生成的正文持久化到 30 天，与导入批次只存计数不存原文的隐私口径相悖。
- Cookie 固定 SameSite=Lax（技术设计 §7），跨站表单 POST 不携带 Session；本路由不返回任何项目数据与用户资料。
- 事务边界：路由全程不开启数据库事务、无 SQL 写；上游调用与任何数据库操作互斥，不存在事务内网络请求。
- 密钥管理：只从 `AI_ASSIST_API_KEY_FILE` 指向的 Secret 文件读取（fail closed）；不进日志、不进审计、不进错误响应。
- 数据出网：抽取后的文本经服务端转发到管理员配置的端点（中转站或自建）；文件本身不出浏览器。弹窗固定提示「内容将经服务端发送到管理员配置的 AI 服务用于生成草稿，请勿包含敏感信息」；端点的可信性与其数据政策由部署方负责，部署文档需记录该出网行为。
- 日志：只记录调用元数据（时间、模式、模型、输入字符数、结果状态、耗时），不记录正文与密钥；本路由无业务状态变化，不写审计。

### 2.6 前端交互

- 导入弹窗 INPUT 阶段新增「AI 分析我的文档（可选）」区块：「选择文档」+ 粘贴框两个入口 + 分析按钮；模式跟随当前导入入口自动取值，不单独选择。
- 选择文档并抽取成功后自动开始一次分析（无自动重试）；粘贴文本走「开始分析」按钮。生成中禁用入口并显示进度；成功后把 markdown 填入导入文本框（文本框已有非空内容时先二次确认将覆盖当前内容）；`issues` 非空时在文本框上方列出，ERROR 级别显著提示。
- 失败按错误码映射固定中文提示（未启用 / 超时 / 上游限流 / 上游故障 / 上下文超限 / 输入超限 / 抽取失败）；「未启用」不做入口隐藏（不新增部署期运行时配置下发接口）。
- 所有请求走生成客户端；不新增裸 `fetch` / `axios`。

### 2.7 规模与配额

- 输入文本 200000 字符（契约固定；超过 100000 字符前端非阻断提醒）、文件 20 MiB、输出 200000 字符（响应 Schema 上限，超出按上游响应非法处理）。
- 用户级额度、用量统计与独立限流不在本期（用户明确额度先不管）；异常使用由管理员通过开关与端点侧额度处置；后续如需要，另立 ADR。

### 2.8 非目标

1. 不做浏览器直连上游（密钥不下发浏览器、CSP 不放开）；
2. 不做多轮对话式修改、流式输出与自动重试；
3. 不读取项目现有数据（模块 / 功能 / 任务等）拼提示词，仅分析用户提供的文本（无 RAG）；
4. 不做 AI 结果直接导入或跳过预览（必须人工确认）；
5. 不做 `.doc`（旧版二进制）、`.pptx`、图片输入与扫描件 OCR；不做服务端文件上传 / 接收 / 解析（文件始终只在浏览器本地抽取）；
6. 不做分块多次调用与自动续写——超长文档请精简或分多次生成草稿；
7. 不做用户级配额与计费统计；
8. 不新增数据库表 / 迁移 / 审计事件；新增前端依赖仅限文本抽取所需（走独立依赖 PR）。

## 3. 影响

- 契约：新增 `DocumentImportAssistRequest` / `DocumentImportAssistResponse` Schema（`issues` 复用 `DocumentImportIssue`，`text` 上限 200000）；新增 1 条路由（106 → 107）；`pure-validation.ts` allowlist 加 1 个成员；OpenAPI 与生成客户端重生成，`contract:validate` / `contract:drift` 覆盖。
- API：`apps/api/src/modules/document-import/` 新增 AI 配置加载（fail closed）与 OpenAI 兼容出站适配器；HTTP service 新增组装提示词 → 调上游 → 解析器预检 → 组装响应的编排；Controller 只绑定 operationId；无数据库改动。
- 前端：`DocumentImportModal.tsx` 新增 AI 区块与状态、错误码文案；`document-import-query.ts` 增加生成调用；新增本地抽取模块（txt / md 直读、docx、pdf 三分支与错误提示）与 `mammoth` / `pdfjs-dist` 两个懒加载依赖（独立依赖 PR、锁定精确版本）。
- 运维：`deploy/compose.yaml` 增加 `AI_ASSIST_*` 接线与（启用时）Secret 挂载；`apps/ops` 增加管理员自检脚本（探测端点 / 密钥 / 模型可用性；不新增根级命令、不纳入 CI）。
- 文档：功能设计 / 系统设计 / 技术设计同批增补（接受后已去掉草案标注）；权限矩阵新增 `assistDocumentImport` 行、测试矩阵新增 `DOC-IMPORT-AI-*` 行（均已随本批落库）。

## 4. 验证

- 单元：配置 fail-closed 矩阵（关闭 / 缺端点 / 缺模型 / 缺密钥文件 / 密钥为空 / 端点非 https）；提示词组装快照（模板文本、模式约束、用户资料独立 message）；适配器请求构造与错误映射（本地 stub，含 `context-limit` 与 `finish_reason: length` 截断追加 ERROR 问题）；输出超长 / 空内容 / 非法 JSON 拒绝路径。
- 客户端抽取：用脚本生成的最小 `.docx` 与文本型 `.pdf` 夹具验证抽取正确；扫描件 / 无文本 PDF 提示；`.doc` / `.pptx` 拒绝；超 20 MiB 与超 200000 字符提示；`.docx` / `.pdf` 依赖懒加载（主包体积不增）。
- 契约：`pnpm contract:validate`（107 条路由与纯校验 allowlist 校验通过）、`pnpm contract:generate` 与 `contract:drift`。
- 集成：本地 stub 上游 + 真实 PostgreSQL，断言 200 全链路、401 匿名、422 输入超限、503 未启用 / 上游故障，并断言该路由不产生任何数据库写入。
- E2E：stub 上游走真实 UI（打开弹窗 → 选择 `.docx` 夹具 → 自动分析 → 草稿填入 → 预览 → 确认导入）；CI 不访问真实外网。
- 安全门禁：`check:secrets`（新变量命名与 Secret 路径）、PDF Worker 与 CSP 兼容实测（不放宽 `script-src` / `style-src`）、依赖 PR 人工确认与 lockfile 检查、权限矩阵校验、文档检查。

## 5. 风险、回滚与确认要点

- 内容出网：抽取后的文本离开 InPulse 边界经中转站处理（文件本身不出浏览器）；部署方需选择可信端点并知悉其数据政策；UI 与部署文档双提示。这是本 ADR 引入的主要新风险。
- 上游不可用 / 不稳定：fail closed + 固定 503 错误码；不自动重试；不影响现有手工粘贴与文件导入链路（完全独立）。
- 扫描件 / 加密 PDF：无 OCR，抽取不到文本时明确提示改用粘贴或先转文本。
- 大文档截断：模型上下文与输出上限可能截断结果，以 ERROR 级问题清单提示并建议精简或分次生成。
- 计费不可控：额度按用户决定暂不设限；管理员可用 `AI_ASSIST_ENABLED=false` 即时停用或收回端点密钥。
- 提示注入：输出永远经解析器与人工预览双重把关；AI 无任何直接写库路径。
- 回滚：关闭开关或移除配置即恢复现状；无数据库迁移、无 InPulse 侧数据残留（除服务端日志元数据与中转站侧记录）；前端依赖升级或移除走独立依赖 PR。
- 确认要点（2026-10-13 随接受生效）：① 单一 `assistDocumentImport` 路由承载两种模式（取值 `IN_PROJECT` / `WHOLE_PROJECT`）；② 模板常量迁入 `packages/api-contract` 作为唯一来源；③ 把 `assistDocumentImport` 加入纯校验 allowlist（csrf / idempotency 均为 none）及不引入幂等记录的隐私理由；④ 503 `AI_ASSIST_DISABLED` 与 `AI_ASSIST_UPSTREAM_FAILED` 对既有 503 语义（就绪探针）的扩展；⑤ 新增前端依赖 `mammoth` 与 `pdfjs-dist`（独立依赖 PR、懒加载、锁定精确版本、许可与 PDF Worker / CSP 实测）；⑥ 输入 200000 字符上限与「超 100000 字符非阻断提醒 + 截断时 ERROR 提示」的规模口径。
