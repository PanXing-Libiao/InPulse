# ADR-085 项目物理删除保留项目审计链

- 状态：Accepted
- 日期：2026-10-19
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-062](ADR-062.md) 的 §2.1.1、§2.4、§3 与 §4.5；修订 [ADR-008](ADR-008.md) 中“项目删除可清空项目审计链”的唯一例外口径；沿用 ADR-062 的物理删除、权限、幂等与 SYSTEM 链 project.delete 留痕

## 1. 背景

ADR-062 把项目删除改为不可逆物理删除，并在同一事务内删除项目自己的 `PROJECT:<id>` 审计链，只保留 SYSTEM 链的一条 `project.delete`。用户随后明确要求：项目删除时审计日志的那些记录也要保存下来。

审计日志的核心价值是事后追溯，不能因为被审计的业务实体消失而一起消失。删除项目是业务数据的物理清除，不应等同于删除已经发生过的历史事件。因此本次保留项目审计日志与链头，业务数据仍按 ADR-062 物理删除。

## 2. 决策

1. `app.purge_project(integer)` 继续删除项目行及其全部下级业务数据，但**不再删除** `app.audit_logs` 与 `app.audit_chain_heads`。项目自己的 `PROJECT:<id>` 链、序号、前后哈希与链头原样保留。
2. 删除 `audit_logs.project_id` 与 `audit_chain_heads.project_id` 指向 `app.projects(id)` 的外键。删除后 `project_id` 是历史审计坐标，不再要求当前项目行存在；`chain_id = 'PROJECT:<id>'` 与 `project_id` 的一致性 CHECK 保持不变。
3. 项目 ID 仍由 identity 序列单调分配、不得复用；项目编码可复用，但不影响历史审计链的项目 ID 坐标。删除事件 SYSTEM 链的 `project.delete` 继续记录项目编码、名称、状态、行版本、操作者角色与删除计数。
4. `project.delete` 载荷的计数增加 `retainedAuditLogs`，表示本事务保留的项目链审计行数；`total` 只统计被物理删除的业务数据行，避免把“保留”误读为“删除”。
5. 删除后的项目链只读冻结，不追加新事件。系统管理员仍可通过 `GET /api/v1/audit-logs?projectId=<id>` 读取该链，也可通过 `chain=all` 在全部链中查看；普通用户与项目成员没有读取权限。
6. 前端删除确认必须明确“业务数据删除、历史审计链保留”，不得再声称项目审计链随项目清除。

## 3. 影响与代价

- 好处：审计历史不再因项目删除而消失；项目链的哈希链可继续用既有工具校验；备份与审计归档自动覆盖保留数据。
- 代价：审计行可以引用已不存在的项目，数据库不能再以普通外键表达“历史引用”。读取仍只依赖 `project_id`/`chain_id`，不需要项目行存在。
- 项目名称在审计页可能回退为 `项目 #id`；删除事件载荷仍保留当时的编码与名称，且项目编码复用不会改变历史链的项目 ID。
- 迁移只保证**此后**的项目删除保留审计链；迁移前已由旧 `app.purge_project` 删除的项目链已物理消失，本迁移不会重建或伪造历史。
- 不改变删除权限、返回码、请求体、幂等摘要与重放授权；不新增路由、数据库角色或依赖。

## 4. 非目标

1. 不恢复项目软删除、回收站、还原或保留期自动清理。
2. 不向普通用户公开已删除项目的审计链。
3. 不删除、重写或重新计算任何历史审计行/链头。
4. 不为已删除项目重新开启业务写入或新审计事件。

## 5. 验证

- 迁移 `0049_project_delete_audit_retention.sql`：外键移除、purge 函数不再包含审计 DELETE、项目链与链头保留。
- 真实 PostgreSQL 集成：删除项目后业务表为零、`audit_logs` 与 `audit_chain_heads` 保留，管理员按 `projectId` 与 `chain=all` 仍能读取。
- 回归：项目删除权限、幂等重放、编码复用、SYSTEM 链完整性与前端删除提示文案。
