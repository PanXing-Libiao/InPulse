# ADR-101 Casdoor 导入按应用 Permission 收窄候选账号

- 状态：Accepted（§2、§3 与 §5 中按 Permission scope 二次收窄候选账号群组的决策已由 [ADR-107](ADR-107.md) 修订）
- 日期：2026-10-27
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-100](ADR-100.md) §2.1 与 §4 的候选目录口径；保持 ADR-032、ADR-097、ADR-098、ADR-099 的身份映射与组织同步不变

## 1. 背景

ADR-100 的 Casdoor 批量导入以配置 organization 下所有启用账号为候选范围，再把启用中的 Physical 群组写成 InPulse 组织。正式 Casdoor 的应用权限已经固定在 Permission `permission_inpulse`，其角色 `inpulse_role` 只允许指定群组获得 InPulse 访问；继续读取整个 organization 会把大量无应用权限的账号显示在导入预览中。

## 2. 决策

- 新增非敏感配置 `CASDOOR_IMPORT_PERMISSION`。它只接受单个 Casdoor Permission 名称，必须同时配置 `CASDOOR_IMPORT_ORGANIZATION`。
- 配置后，在读取 Casdoor 用户目录和解析 Physical 群组之前，先用同一 SSO application 的 clientId/clientSecret 通过 HTTP Basic 读取：
  - `GET /api/get-permission?id=<organization>/<permission>`
  - Permission 引用的 `GET /api/get-role?id=<owner>/<role>`，递归读取嵌套角色
- 候选账号只保留 Casdoor 用户 ID 直接命中 Permission / Role `users`，或用户 groups 命中 Permission / Role `groups` 的账号。
- 对命中的账号，用户 groups 还必须按同一 Permission scope 再次收窄；只有 scope 内群组会进入 Physical 解析和组织同步。直接命中用户但没有允许部门的账号进入未分类，不保留其它未授权部门。
- Permission 必须启用、effect 为 `Allow`、state 为 `Approved`；所有引用必须属于同一 organization。角色停用时忽略；权限范围为空的 configuration 一律拒绝。
- Permission、Role、群组读取失败、跨 owner、嵌套过深或分页/数量超限时，管理员导入接口返回 503 fail closed，不降级为全量目录。
- 过滤只决定“哪些 Casdoor 账号可以进入管理员导入候选”，不把 Casdoor Role / Permission 映射为 InPulse 权限，不改变 SSO 登录时的身份映射、组织同步或管理员勾选确认。
- 未配置该变量时保持 ADR-100 的原有行为，供没有对应 Permission 的本地和测试环境使用。
- 正式环境配置为 `CASDOOR_IMPORT_PERMISSION=permission_inpulse`；后续部门权限变化由 Casdoor Permission / Role 本身维护，不在 InPulse 硬编码部门名单。

## 3. 影响

- 当前正式目录 376 个启用账号中，按 `permission_inpulse` 过滤后为 84 个候选账号；仅通过 `Inpulse Group Access` 获得权限、但没有允许部门的账号仍进入未分类，不因过滤丢失访问权。
- 管理员预览的 `scannedUserCount` 表示权限范围内的候选数，不再表示整个 organization 的账号数；最终写入 InPulse 的 Physical 组织同样只来自权限范围，用户的其他未授权部门不会因账号命中而混入。
- 不新增路由、数据库迁移或依赖；新增配置接线与单元测试。

## 4. 非目标

1. 不把 Casdoor 权限本身复制成 InPulse 项目或管理员权限。
2. 不自动停用、删除或重新启用平台账号。
3. 不增加后台定时同步或 Webhook。
4. 不硬编码 Permission / Role / 部门名称；具体范围始终以 Casdoor 配置为准。

## 5. 验证

- API 单元：Permission / Role 解析、嵌套角色、允许用户和群组合并、disabled / Deny / Pending / 跨 owner / 空范围 fail closed。
- API 单元：目录过滤只把命中权限范围的账号送入组织解析，未命中账号不产生候选。
- 配置测试：Permission 必须与 organization 同时配置，只接受单个资源名称。
- Web 文案与既有 Casdoor 导入测试回归。

## 6. 后续修订

2026-10-29 [ADR-107](ADR-107.md) 修订本 ADR 的群组二次收窄口径：Permission 仍只决定哪些账号进入候选范围；候选账号命中后保留其全部组引用，并继续按 ADR-099 / ADR-100 只解析启用中的 Physical 实体组。本节其余候选范围、fail closed 与非授权映射决策不变。
