# ADR-108 SSO 组织同步审计仅在变更时记录

- 状态：Accepted
- 日期：2026-10-30
- 决策人：项目负责人（用户指示）
- 关联：修订 [ADR-097](ADR-097.md) §2.1 与 §2.5 的审计口径；保持每次成功 SSO 登录全量对账、同事务写入与 ADR-098 / ADR-099 的实体组过滤不变

## 1. 背景

每次成功 SSO 登录都会执行组织同步，但原实现无论组织层级或成员关系是否变化，都会写一条 `auth.sso_organizations_synced`。例行重复登录因此常同时出现 `auth.sso_login` 与 `auth.sso_organizations_synced`，审计噪音过高，也不利于定位真实组织变更。

## 2. 决策

### 2.1 每次登录仍执行组织对账

- `groups` 存在时，每次成功登录仍在签发 Session 的同一事务内重新计算 Casdoor 实体组、组织层级和直接成员关系。
- `groups` 缺失时仍表示本次未提供组织事实：登录成功、不修改组织、不写组织同步审计。
- `groups` 为空数组或只包含被过滤的 Virtual / 停用组时，仍按现有规则清空现有成员关系并归入未分类；只有确实存在需要清理的关系时才记为变化。
- 对账失败仍不得签发 Session。

### 2.2 仅实际变化时写审计并写成员关系

- 组织同步结果为 `createdOrganizationCount > 0`，或用户直接组织成员关系与本次期望集合不同，即 `changed=true`。
- `changed=true` 时，按现有全量替换语义清理并写入成员关系，并写一条 `auth.sso_organizations_synced` 审计。
- `changed=false` 时，不删除也不重插成员关系，不写 `auth.sso_organizations_synced`；正常登录只保留 `auth.sso_login`，首次开通或账号绑定另保留对应账号审计。
- 审计 payload 继续记录 `groupsClaimPresent`、`groupCount`、`createdOrganizationCount` 与 `membershipCount`，不记录 Token、Session、Secret 或组路径明细。
- 不删除历史审计；本决定只约束后续登录。

### 2.3 无新增接口或数据变更

- 不新增路由、迁移、配置项或依赖，路由总数保持 133。
- 管理员 Casdoor 导入仍使用同一组织同步端口，不改变导入语义与计数；该端口新增 `changed` 只表达本次同步是否实际写入。

## 3. 影响

- 常规重复登录从两条审计降为一条 `auth.sso_login`。
- 首次建立组织、切换实体组、清空组织、新增祖先组织等真实变化仍可在审计中追溯。
- 无变化时减少一次 DELETE 与若干 INSERT，降低登录事务写入量；对账读取仍保留，以发现 Casdoor 侧变化。
- 审计页面的中文映射不变，既有历史记录无需迁移。

## 4. 非目标

- 不停止每次登录的组织对账，也不改为定时同步或 Webhook 同步；
- 不把改变成员关系以外的个人资料更新写入组织同步审计；
- 不删除、合并或重写既有审计记录；
- 不改变 Casdoor 权限、组织只读边界或 InPulse 授权模型。

## 5. 验证

- 真实 PostgreSQL + 桩 IdP 覆盖首次无组登录、同一实体组重复登录、`groups` 缺失、空数组清空和组替换：仅实际变化产生 `auth.sso_organizations_synced`。
- 账号首次开通与既有账号绑定在 `groups` 缺失时分别只写账号审计与 `auth.sso_login`。
- 定向 `sso-login.integration.test.ts` 22 例通过；API typecheck 与变更文件 Prettier 检查通过。
- 不声称未执行的全量 CI、Playwright、测试 VM 部署或真实 Casdoor 联调已通过。
