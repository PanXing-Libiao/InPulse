# ADR-068：AI 辅助转换改为管理员在线配置（密钥信封加密落库）

- 状态：Accepted（2026-10-13 接受，实现随本批落库）
- 日期：2026-10-13
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-067](ADR-067.md) 的 §2.2（配置来源）与 §2.5（密钥管理）：配置门控从“仅环境变量”扩展为“管理员在线配置优先，环境变量保留急停与遗留回退”；密钥从“仅 /run/secrets/* Secret 文件”扩展为“数据库密文 + /run/secrets/* 主密钥文件”。扩展 [ADR-019](ADR-019.md) 校验规则——把 `testAiAssistSettings` 加入纯校验 allowlist。沿用 [ADR-004](ADR-004.md)（契约生成）、[ADR-029](ADR-029.md)（统一错误体与响应校验）、[ADR-013](ADR-013.md)（事务边界）、[ADR-031](ADR-031.md)（管理员高风险门禁不再要求 TOTP）、[ADR-032](ADR-032.md)（Secret fail-closed 先例）。新增 3 条路由（107 → 110），新增迁移 `0040`。

## 1. 背景

用户原话要点：

> 那能不能设置一个口子可以让管理员配置启动AI辅助模型

随后在两种方案中选择方案二：管理员在后台页面自助配置（含填写 API 密钥），密钥不得明文落库。

- 现状（ADR-067）：启用与端点 / 模型 / 密钥全部由部署环境变量与 `/run/secrets/ai_assist_api_key` 决定；改配置必须改环境变量并重启容器，管理员无法自助。
- 方案一（已否决）只允许管理员配置非敏感项、密钥继续由运维放 Secret 文件；用户明确要求方案二：管理员连密钥也能在页面配置，部署自包含。
- 安全底线：明文密钥不得入库、不得回显、不得进入日志 / 审计 / 幂等物化 / 错误响应；主密钥不得进数据库，只能从 `/run/secrets/*` 读取并 fail closed。

## 2. 决策

### 2.1 三条管理员路由

- `GET /api/v1/admin/ai-assist`（`getAiAssistSettings`）：读取当前生效配置与状态；永不返回密钥明文或密文，只返回 `keyHint`（密钥尾 4 位）与 `keyConfigured`；响应 `no-store`。
- `PUT /api/v1/admin/ai-assist`（`updateAiAssistSettings`）：单行配置整体替换语义，`enabled / endpoint / model / timeoutMs / maxTokens` 必填；`apiKey` 可选（缺省或 null = 保持不变；填写 = 校验后加密替换）。启用而既无新密钥也无已存密钥时 422。CSRF、`Idempotency-Key` 必填（数据库级幂等），同事务写审计 `admin.aiAssistSettings.update`（审计只含端点、模型、开关、超时 / 上限与 `keyChanged`，绝不含密钥）。
- `POST /api/v1/admin/ai-assist/test`（`testAiAssistSettings`）：用当前生效配置向上游发送 `max_tokens=1` 最小探测请求，验证端点 / 密钥 / 模型可用；不写任何持久化状态、不发用户数据、不写审计，加入纯校验 allowlist（csrf / idempotency 均为 none）。响应 200 `{ ok, reason, model }`，`reason` 为固定分类。
- 三条路由均为 `authPolicy: adminSession`，非管理员 403、匿名 401；路由 107 → 110。

### 2.2 配置来源与优先级（修订 ADR-067 §2.2）

1. 急停（最高优先）：`AI_ASSIST_ENABLED` 显式为非空且非 `1` / `true`（如 `0`、`false`）时，无论数据库如何一律关闭；Compose 默认值由 `0` 改为空串，使“未设置”与“显式关闭”可区分。
2. 数据库配置：`app.ai_assist_settings` 存在单行时以其为准（`enabled=false` 即关闭，环境变量不再能强制开启）。
3. 遗留环境变量模式：无数据库行且 `AI_ASSIST_ENABLED=1` 时，沿用 ADR-067 语义（`AI_ASSIST_ENDPOINT` / `AI_ASSIST_MODEL` / `AI_ASSIST_TIMEOUT_MS` / `AI_ASSIST_MAX_TOKENS` / `AI_ASSIST_API_KEY_FILE`），本地开发与测试继续使用；配置非法时按既有口径 fail closed（`CONFIG_INVALID`）。
4. 其余情况：关闭（`NOT_ENABLED`）。

生效方式：assist 与 test 路由每次调用时解析配置（低频操作，无缓存失效与重启问题）；解析读库与解密都在数据库事务之外，网络调用仍严格在事务外。

### 2.3 密钥信封加密

- 算法：AES-256-GCM；密文格式 `nonce(12) || tag(16) || ciphertext`，`api_key_ciphertext BYTEA`，`api_key_key_version INTEGER` 单独成列；AAD 固定为常量字符串 `app.ai_assist_settings.api_key`。
- 主密钥：版本化 keyring 文件（`version:hex` 每行一项，≥64 hex 字符 = 32 字节），由 `AI_ASSIST_ENCRYPTION_KEY_FILE` 指向（部署固定 `/run/secrets/ai_assist_encryption_key`），当前版本由 `AI_ASSIST_ENCRYPTION_KEY_VERSION`（默认 `1`）选择；生产路径只允许 `/run/secrets/*`，仅 `NODE_ENV=test` + `AI_ASSIST_ENCRYPTION_KEY_TEST_PATH=1` 允许临时路径（与 Session / 审计 keyring 同款 fail-closed 规则）。轮换：文件内同时保留旧版本即可解密旧行；换密钥后新写入使用当前版本。
- 只存尾 4 位提示 `api_key_hint`（供管理员核对“是不是换了密钥”），不存完整密钥；密钥原文不落任何表、不写日志、不进审计、不进入幂等重放体（`AiAssistSettings` 响应 Schema 只含 hint）。
- 解密失败分类：主密钥文件缺失 / 非法 / 缺版本 → `ENCRYPTION_KEY_UNAVAILABLE`；GCM 校验失败（密文损坏或密钥不匹配）→ `CONFIG_INVALID`；两种情况都 fail closed，接口统一按未启用处理，管理页展示分类原因。
- 备份影响：数据库备份只含密文；主密钥文件不随库备份，恢复时必须由运维另行保管并同步恢复，否则数据库配置不可解密（fail closed，不会静默降级）。

### 2.4 数据模型（迁移 0040）

- `app.ai_assist_settings` 单行表：`id SMALLINT PRIMARY KEY CHECK (id = 1)`、`enabled`、`endpoint`、`model`、`timeout_ms`（1000～600000）、`max_tokens`（1～200000）、`api_key_ciphertext`、`api_key_key_version`、`api_key_hint`、`updated_by`（FK → `app.users`）、`updated_at`、`row_version`（每次更新 +1）。
- 授权：`app_runtime` 仅 `SELECT / INSERT / UPDATE`（应用永不删除该行），`app_backup` 只读；迁移尾部按既有范式做表属主、约束与最小授权部署校验。
- 表结构只放非敏感与密文；审计链不因配置变更增加明文，只有动作与摘要。

### 2.5 前端交互

- 「成员与设置」页新增「AI 辅助转换」页签：状态卡片（来源：数据库 / 环境变量 / 未配置；就绪状态；失败分类中文提示；密钥尾号；版本与更新时间）+ 表单（启用开关、端点、模型、超时、最大 token、密钥密码框，留空表示不改密钥）+「保存」与「测试连接」按钮。
- 保存走 CSRF + `Idempotency-Key`；测试连接使用已保存配置（保存后再测）；错误按 400 / 401 / 403 / 422 / 429 / 503 映射固定中文提示；密钥字段永不回显。
- 文档导入弹窗的「未启用」错误文案改为同时指向「请管理员在成员与设置中配置」。

### 2.6 安全边界变化声明

本 ADR 对 AGENTS.md 第 7 节「生产 Secret 只从 `/run/secrets/*` 读取」做受控扩展：允许把**由管理员输入的第三方 API 密钥**以 AES-256-GCM 密文存入数据库，加密主密钥仍然只从 `/run/secrets/*` 读取并 fail closed。明文只允许存在于：请求体内（HTTPS 传输）、API 进程内存（解密瞬间）、出站 `Authorization` 头。禁止出现在日志、审计、错误响应、幂等重放记录、数据库明文列与任何仓库文件。

### 2.7 测试与文档

- 单测：加密往返 / 篡改拒绝 / keyring 解析与 fail closed / 配置解析优先级矩阵 / 表单校验。
- 集成（真实 PostgreSQL + stub 上游）：GET / PUT / test 全链路、非管理员 403、CSRF 缺失 403、幂等重放、急停优先、数据库行优先于环境变量、密钥尾号、审计写入、解密失败分类。
- E2E：管理员在设置页保存配置 → 测试连接成功 → 文档导入弹窗经数据库配置完成 AI 转换；用例结束删除单行配置，保证环境变量回退用例可重复。
- 文档同步：功能设计 / 系统设计 / 技术设计、权限矩阵（+3 行）、测试矩阵、AGENTS.md、开发日志与部署文件（compose 新增 `ai_assist_encryption_key` Secret 与 `AI_ASSIST_ENCRYPTION_KEY_*`）。

## 7. 补记（2026-10-15）

按用户「这个关闭就直接显示关闭吧，不用再点击保存了」调整设置页交互：**主开关拨动即落库**，不再要求点「保存配置」。接口未变，仍是 2.2 条的 `PUT /api/v1/admin/ai-assist` 整体替换语义——前端以**服务端已保存**的 `endpoint / model / timeoutMs / maxTokens` 组装请求体、`apiKey` 传 `null`（不改密钥），成功后用 PUT 响应直接更新前端缓存（不再重新 GET + 回填表单，避免把用户正在编辑的字段冲掉），失败则开关回落到已保存状态。因此 2.6 条的「表单（启用开关、端点、模型、超时、最大 token、密钥密码框）+「保存」与「测试连接」按钮」应读作：**除启用开关外的字段**由「保存」提交。尚未配置密钥（无数据库行）时开关只改本地草稿、不发请求，并提示「首次配置必须提供 API 密钥」——与点「保存配置」同一口径，避免出现「已启用但无密钥」的半配置状态。

未改契约、路由、迁移与服务端行为（仍 116 条路由 / 42 个迁移）；覆盖见 [测试矩阵](../test-matrix.md) 的「『AI 辅助转换』主开关拨动即保存」一节与开发日志第一百九十三条。

## 8. 补记（2026-10-30）：可用模型发现

按用户「这个我能不能直接获取有哪些可用模型」的要求，在不改变管理员配置契约与密钥边界的前提下扩展第 4 条管理员纯校验路由：

- `POST /api/v1/admin/ai-assist/models`（`listAiAssistModels`）：请求体为 `{ endpoint, timeoutMs, apiKey? }`；端点与超时直接取设置页当前输入，`apiKey` 有值时只用于本次上游探测，缺省或 `null` 时才通过运行时服务只读复用已保存密钥（数据库行优先，环境变量遗留模式回退）。向上游 OpenAI 兼容 `/v1/models` 发起只读 GET；响应 `{ ok, reason, models }`，`models` 只含去重排序后的模型 ID，失败复用测试连接的固定分类（`AUTH` / `RATE_LIMITED` / `TIMEOUT` / `NETWORK` / `INVALID_RESPONSE` 以及急停 / 配置分类），不透传上游原文。
- 端点推导固定把已规范化路径末尾的 `/chat/completions` 替换为 `/models`，保留同源 query；响应正文超过既有 2,000,000 字符上限或形状非法即拒绝，模型数上限 1,000。
- 发现操作不写数据库、不写审计、不写幂等记录、不发送用户数据，网络调用在数据库事务之外；表单中的一次性密钥只进入请求内存，`AiAssistModelsRequest.apiKey` 登记为敏感字段，不落库、不回显、不写日志。急停开关仍最高优先；已保存数据库行即使 `enabled=false` 也可在管理员继续配置时复用其密钥。加入 ADR-019 纯校验 allowlist，只要求完整管理员 Session。
- 设置页“模型”字段改为可搜索 `AutoComplete`，增加「获取可用模型」按钮；发现请求使用表单当前端点、超时与密钥，因此模型为空、配置尚未保存时也可先发现模型，再选择并保存。成功后直接列出模型名并填充下拉，仍允许手动输入别名。错误按固定中文分类展示。
- 路由总数 121 → 122，未新增迁移。本地实测：`ai-assist.client.test.ts` 18 例、`AiAssistSettingsPanel.test.tsx` 14 例、`admin-ai-assist-api.integration.test.ts` 14 例（真实 PostgreSQL + 回环 stub，覆盖未保存端点 / 密钥与已保存密钥回退）、`settings-ai-assist.spec.ts` 3 例通过；`contract:validate` 122 条路由、`contract:drift` 与 `pnpm build` 通过。测试均使用回环 stub，未把用户提供的真实 API Key 写入仓库或数据库。
