# ADR-095 清理所有历史未分类模块

- 状态：Accepted
- 日期：2026-10-23
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：承接 ADR-030 的空项目规则，替代 ADR-059 中未分类模块不可删除的例外；沿用 ADR-058 的任务删除口径、ADR-062 与 ADR-085 的项目删除口径以及 ADR-008 的审计只追加原则

## 1. 背景

未分类模块来自旧的项目初始化机制。ADR-030 于 2026-09-14 取消默认未分类模块后，新项目允许零模块，生产创建流程不再调用 createUnclassifiedModule；但历史项目仍可能保留 kind 为 UNCLASSIFIED 的模块。

这些模块已经不再承担默认归属职责，却仍受数据库触发器 app.protect_unclassified_module 和删除接口的 409 MODULE_UNCLASSIFIED_PROTECTED 保护，导致模块删除规则不一致。用户明确要求直接物理删除现有项目中的全部未分类模块。

## 2. 决策

1. 新增迁移 0058_cleanup_unclassified_modules.sql，一次性物理删除 app.modules 中全部 kind 等于 UNCLASSIFIED 的行及其业务下级。
2. 删除范围包括这些模块下的全部功能、任务、任务状态历史、负责人、任务影响关系、聚合组成员、外部链接关联、遗留项关联、迭代记录、记录版本、记录遗留项、记录影响关系和搜索投影。
3. 迭代记录不做快照，不保留记录本体或版本；只保留审计、项目动态、项目成员关系和删除后仍需追溯的业务事件。
4. 迁移按固定顺序删除：记录与遗留项下级、记录、任务聚合关系、任务下级、任务、功能外链、功能、模块、搜索投影。删除前固定范围到临时表，避免级联过程中子查询漂移。
5. 未分类模块保护触发器只在本次迁移事务内关闭，提交前恢复。迁移失败时事务回滚，触发器保持原状。
6. 不修改历史迁移，不修改删除接口，也不改变新项目的创建路径。迁移末尾断言所有未分类模块及其业务下级均已清理。

## 3. 影响

- 数据：现有未分类模块及其业务下级永久消失，不可恢复。
- 历史：审计与项目动态不删除；由于迁移没有用户操作上下文，不为每条历史未分类模块伪造删除事件。
- 约束：未分类模块唯一索引和保护触发器保留，防止未来误插入或误删；当前生产路径没有创建新未分类模块的调用方。
- 代码：本轮不改变模块、功能、任务的一般删除接口；它们仍处于后续硬删除改造范围。

## 4. 非目标

1. 不移除模块 kind 字段或 UNCLASSIFIED 枚举。
2. 不删除未分类模块之外的普通模块。
3. 不删除审计、项目动态、项目成员、外部链接主表或项目本身。
4. 不提供回收站、还原或导出后删除。
5. 不把历史未分类模块转换为普通模块。

## 5. 验证

迁移 0058 已在本地 PostgreSQL 18.6 实例执行。演示库清理前有 1 个未分类模块、2 个任务和 1 条迭代记录，执行后未分类模块、其任务和记录均为 0，普通模块保留。大型测试库清理了 2439 个未分类模块、1316 个功能、1076 个任务和 887 条迭代记录，延迟约束结算与迁移末尾断言通过。另用事务回滚验证跨模块聚合组：只删除未分类任务成员，普通模块任务保留，组转为 CLOSED、剩余成员转为 DETACHED。database 集成测试 2 文件 29/29、迁移格式检查与文档门禁通过；应用级真实 E2E 尚未执行。
