# ADR-083：移除管理员强制退出（forceLogoutUser）

- 状态：Accepted
- 决策日期：2026-10-19
- 接受依据：用户 2026-10-19 明确要求「彻底删除」强制退出。此前成员页已不再展示入口，但 `forceLogoutUser` 路由、服务端命令、权限矩阵与生成客户端仍然保留。
- 关联：替代 [ADR-082](ADR-082.md) 中「强制退出保持不变」的决策，以及 [ADR-032](ADR-032.md) 决策 11 中以 `force-logout` 作为离职回收能力底座的条款；路由总数 126 → 125；无迁移、无依赖变化。

## 1. 背景

- 成员页当前只提供「启用 / 停用 / 编辑 / 强制删除」。启用账号为「停用、编辑」，停用账号为「启用、编辑、强制删除」，已没有任何强制退出入口。
- 但 `POST /api/v1/admin/users/{userId}/force-logout` 仍暴露在 Route Registry、权限矩阵、OpenAPI、生成客户端和 API 集成测试中，形成「无界面但有写接口」的残留能力。
- 停用账号已在同一事务内递增 `users.auth_version`、撤销全部 Session，并写 `admin.user.disable` 审计；管理员需要让目标立即下线时，停用已经覆盖该语义。保留只撤销 Session、不改变账号状态的独立强退接口，会扩大写接口面并增加权限与幂等维护成本。
- 用户明确要求彻底删除，而不是继续兼容保留。

## 2. 决策

- 删除 Route Registry 中的 `forceLogoutUser` 条目和权限矩阵条目；用户管理路由由 7 条降为 6 条，全局路由总数 126 → 125。
- 删除 `AdminUsersController` 的 `POST :userId/force-logout` 绑定、`AdminUsersHttpService` 的强退分支、`AdminUserService.forceLogout` 与 `AdminUserRepository.forceLogout`。
- `AdminUserError` 的自操作文案不再包含「强制退出」；停用、编辑、删除的自操作保护保持不变。
- 重新生成 OpenAPI、路由指纹与 Web 生成客户端；客户端不再声明或实现 `forceLogoutUser` 方法。
- 前端不恢复任何强制退出按钮、弹窗或调用；E2E 与 Web 单测中的强退链路和入口断言一并删除。
- 不新增数据库迁移。`users.auth_version`、Session 撤销与失效切片继续服务停用、改密等既有流程。
- 历史审计中的 `admin.user.force_logout` 事件、原始载荷与哈希链保持不可变；前端保留该动作码的中文展示标签，避免旧审计行退化为原始码，但不再产生新事件。
- 旧客户端若继续调用该路径，将因路由不存在而返回 404；本 ADR 不提供弃用期或兼容 shim。自助 `logout` 不受影响。

## 3. 非目标

- 不删除停用账号时的 Session 撤销能力，也不改变 `auth_version` 机制。
- 不清理、不改写历史审计事件与操作日志。
- 不改变 SSO、Session 签发、CSRF、幂等、`If-Match` 与管理员门禁规则。
- 不提供替代的「强制下线」接口；需要立即阻止目标继续访问时使用停用。

## 4. 后果与验收

- `permissions:check` 为 125 条操作 / 125 条路由；`contract:drift` 6 个生成产物一致；Controller 扫描不再出现 `POST .../force-logout`。
- 真实 API 集成不再包含强退步骤；成员生命周期覆盖创建、编辑、停用、启用、删除与墓碑约束。
- Web 成员页不存在强制退出入口；Playwright 覆盖编辑、停用、筛选、启用、强制删除与墓碑消失路径。
- 历史审计动作 `admin.user.force_logout` 仍可显示中文，但新代码路径无法再写入该动作。
