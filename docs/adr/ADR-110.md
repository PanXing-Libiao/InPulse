# ADR-110：AI 助手分场景模型选择与输出上限

- 状态：Accepted
- 决策日期：2026-11-02
- 接受依据：用户确认先实施低风险阶段，以缩短任务助手、文档导入助手与迭代总结助手的响应时间。
- 修订范围：扩展 [ADR-067](ADR-067.md) 的出站模型选择与输出预算，扩展 [ADR-068](ADR-068.md) 的在线配置字段，并修订 [ADR-076](ADR-076.md) 把“新增 AI 配置项”列为非目标的限制。历史 ADR 保留，不修改其当时结论。

## 背景

任务助手、文档导入助手与迭代总结助手原先共用同一个支持视觉的模型，并共用设置页的全局最大输出 tokens。最初方案是让所有纯文本请求改走更快的文本模型；真实上游 A/B 后结论相反：当前 `deepseek-v4-flash-vision-exp` 在短任务与文档草稿上最快，`qwen3.8-flash` 明显更慢，`gemini-3.8-flash` 只在较长的迭代总结上有优势。

### A/B 实测

同一本地 API、同一上游端点、同一提示词，单次调用耗时：

| 场景 | 输入规模 | 当前视觉模型 | gemini-3.8-flash | qwen3.8-flash |
|---|---:|---:|---:|---:|
| 任务助手 3 条平均 | 短文本 | **3,128 ms** | 6,529 ms | 13,161 ms |
| 文档导入 | 595 字 | **4,763 ms** | 7,227 ms | 未测 |
| 迭代总结 | 4,281 字 | 7,421 ms | **5,685 ms** | 未测 |
| 迭代总结 | 约 1,900 字 | **5,968 ms** | 8,754 ms | 22,179 ms |

因此不能把所有文本请求统一切到文本模型，否则会拖慢最常用的任务助手与文档导入。

## 决策

### 1. 分场景模型

1. 任务助手与文档导入始终使用 `model`；文档带不带截图都一样，保证视觉能力并保留当前最快的路径。
2. `app.ai_assist_settings` 新增可空 `summary_model`，只服务迭代总结。
3. `summary_model` 为空时总结也回退 `model`；环境变量遗留模式新增可选 `AI_ASSIST_SUMMARY_MODEL`。
4. 模型选择完全由服务端按场景决定；客户端不得提交模型名，也不得指定任意上游。
5. 日志记录本次实际使用的模型，便于继续按场景做 A/B；仍不记录正文、图片或密钥。

### 2. 分场景输出上限

每次请求仍受全局 `maxTokens` 约束，实际发送值为两者较小者：

| 场景 | 场景上限 | 说明 |
|---|---:|---|
| 新建任务 AI 识别 | 1200 | 输出为固定 JSON 草稿，沿用既有上限 |
| 文档导入纯文本 | 6000 | 模板草稿通常远低于该值 |
| 文档导入带截图 | 不额外收紧 | 视觉提取可能需要更多输出预算，继续使用全局上限 |
| 迭代总结改写 | 3000 | 只输出一段摘要，避免长尾生成 |

收紧上限不是主要提速手段，但能阻止模型在简单场景生成过量内容，并让延迟更可预测。

### 3. 配置、契约与审计

1. 迁移 `0066_ai_assist_text_model.sql` 先增加可空列；A/B 后由 `0067_ai_assist_summary_model.sql` 将列与约束重命名收敛为 `summary_model`。不改写既有配置行。
2. `AiAssistSettings` 响应新增 `summaryModel`；`AiAssistSettingsUpdateRequest` 新增可选可空 `summaryModel`。整体替换语义下缺省按 `null` 处理。
3. `updateAiAssistSettings` 的幂等契约版本升为 `1.1.0`，幂等重放字段加入 `summaryModel`；旧 Key 在新契约下返回 409。
4. 设置页不新增单独字段，继续只展示主模型；`summaryModel` 保留为服务端 / 环境变量覆盖能力，默认空值回退 `model`，避免增加管理端认知负担。
5. 本 ADR 不新增权限能力，仍只服务完整管理员会话。

## 影响

- 未配置 `summary_model` 的既有部署行为不变，仍使用主模型。
- 管理员可为长迭代总结选择 `gemini-3.8-flash`；任务助手与文档导入不会被切到更慢的模型。
- 文档导入带截图仍保留全局输出预算，避免视觉提取被过早截断。
- 日志中的 `model` 字段反映本次实际模型，A/B 结论可复核。

## 非目标

1. 不实现流式输出；普通 POST JSON 契约保持不变。
2. 不做按用户、按项目或按时段的自动模型路由，也不自动评分模型质量。
3. 不持久化用户请求正文、图片或总结结果。
4. 不拆分迭代总结请求，也不增加浏览器缓存。
5. 不改变上游端点、密钥加密、失败分类、超时上限或管理员授权。

## 验证

- 单元测试覆盖：任务与文档使用主模型、总结使用 `summaryModel`、空值回退、三类场景的 `max_tokens` 上限。
- 集成测试覆盖：保存并读取 `summaryModel`、旧请求不传时按 null 保存、幂等重放字段包含 `summaryModel`。
- 前端测试覆盖：设置页不展示总结模型字段；保存配置与主开关保存时保留服务端已有 `summaryModel`（缺省为 null）。
- 契约生成与漂移检查、权限矩阵检查、类型检查、lint 与构建必须通过。
- A/B 数字来自 2026-11-02 本地真实上游单次调用，只作为本次选型依据，不作为长期 SLA。
