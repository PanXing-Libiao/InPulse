# ADR-098 SSO 组织收敛为最深实体群组与未分类展示

- 状态：Accepted
- 日期：2026-10-27
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-097](ADR-097.md) §2.1、§2.2、§2.5、§2.6；沿用 [ADR-081](ADR-081.md) 的组织成员模型，以及 ADR-023、ADR-029、ADR-032、ADR-075 的既有安全与事务边界
- 修订：2026-10-27 [ADR-099](ADR-099.md) 在路径祖先收敛之前增加 Casdoor 群组类型过滤，Virtual 与停用 Physical 组不进入直接成员关系；其余实体组口径与未分类展示保持不变（群组元数据通过 application Basic 读取）。
- 修订：2026-10-27 [ADR-103](ADR-103.md) 取消管理员“成员与角色”页的“未分类”筛选页签；虚拟分类、行内徽章与 SSO 对账口径保留。

## 1. 背景

Casdoor application 使用 `JWT-Custom`、Token fields 为 `Groups`、Token group format 为 `Path` 时，`groups` claim 返回完整群组路径。群组支持父子层级，用户可属于多个真实群组；同一次 claim 也可能同时出现父级路径与用户实际选中的实体群组路径。

ADR-097 首版把每个 claim 路径都写成用户的直接组织，因此同一路径族中的父级会与最深群组一起显示，造成 Casdoor 页面只有一个实体群组、InPulse 却展示多个组织的现象。同时，没有任何组织的账号只显示“未分配”，缺少明确的“未分类”归类。

用户要求只识别和展示实际实体群组，并把无群组人员归入“未分类”。

## 2. 决策

### 2.1 实体群组口径

- 原始 `groups` claim 仍按 ADR-097 校验完整路径；格式非法仍按 `token-invalid` 拒绝登录。
- 同一 owner 下，如果路径 A 是路径 B 的完整路径祖先（按 `/` 分段边界判断），且 A、B 同时出现在本次 claim 中，则 A 只用于建立组织层级，不写为用户的直接成员关系；只保留最深的 B。
- 互不为祖先的实体群组仍全部保留。InPulse 不把多个真实群组强行截断为一个，也不自行猜测主群组；若希望 Casdoor 用户在 InPulse 只显示一个实体群组，应在 Casdoor 中只配置一个实际群组归属。
- 祖先群组仍按完整路径建立 `app.organizations` 行与 `parent_id` 层级；它们不会因为用户登录而自动获得成员。
- 审计 `groupCount` 与 `membershipCount` 记录收敛后的有效实体群组数；`createdOrganizationCount` 仍记录本次实际新建的祖先与实体组织数。

### 2.2 对账与未分类

- 每次成功 SSO 登录仍在签发 Session 的同一事务内全量对账，删除该用户旧组织关系后只写入有效实体群组。
- `groups` 字段缺失时不修改组织；`groups: []` 清空组织关系；claim 合法但没有可保留的实体群组时同样清空关系。
- 无组织成员统一归入虚拟分类“未分类”。该分类不是数据库组织，不参与 CASDOOR/LOCAL 来源约束，不授予项目权限，也不能通过组织接口加入或删除。
- 已无成员的历史祖先组织行继续保留；管理员页只展示有成员的组织标签，因此不会把祖先组织当成用户实体群组展示。

### 2.3 页面展示

- 管理员“成员与角色”增加“未分类”标签，统计当前启用或停用筛选范围内无组织的账号；无组织账号行内徽章改为“未分类”。
- 批量移出组织后的提示与操作按钮统一使用“未分类”；SSO 账号仍禁止手工组织调整。
- 普通成员无组织时显示“当前为未分类”，说明本地账号与 SSO 账号各自的检查方式。
- 新建项目成员选择器把无组织候选人的分组文案改为“未分类”；“未分类”不是真实组织，不提供整组全选。
- CASDOOR 实体组织继续按末级名称展示，完整路径只作为悬停提示与同步身份。

### 2.4 兼容与边界

- 不新增路由、不修改 OpenAPI/生成客户端/Database Schema/迁移，不改变权限矩阵。
- 已存在的祖先成员关系在下一次成功 SSO 登录时按新口径替换；本轮不写数据迁移、不根据单次 Token 删除组织行。
- 不调用 Casdoor Admin API 或全量目录接口，不记录原始 Token 或完整 claim；ADR-099 限定的 application Basic 单组类型读取除外。

## 3. 影响

- 同一路径族的父级路径不再出现在用户组织徽章或组织标签中，Casdoor 中的一个实体群组在 InPulse 中只对应一个实体组织成员关系。
- 合法的独立多群组仍受支持，不会因本次收敛而丢失。
- 无组织账号有稳定、可筛选的“未分类”出口，管理员不再需要在“未分配”与空组织标签之间猜测。

## 4. 非目标

1. 不为每个用户固定选择某一个群组，也不读取 Casdoor Admin API 推断主群组；ADR-099 仅按已验签 claim 读取具体组的 Physical/Virtual 类型。
2. 不删除已消失群组或已无成员的祖先组织行。
3. 不把“未分类”落库为真实组织，不改变用户、项目或管理员权限。
4. 不改变 SSO state、nonce、PKCE、JWKS、Session、首管理员和 CASDOOR 只读规则。

## 5. 验证

- API 单元：父级与子级同时出现时只保留最深层实体群组；独立群组与不同 owner 的同名路径不受影响；非法路径仍被拒绝。
- API 集成（真实 PostgreSQL + 桩 IdP）：claim 同时携带父级和实体群组时只写实体成员关系；多分支独立群组全部保留；`groups: []` 清空后归入未分类；缺失 claim 不修改。
- Web 单元：管理员页显示“未分类”标签并按无组织筛选；行内徽章、批量移出提示、普通成员空态与项目成员选择器文案一致。
- Playwright：管理员用户页的无组织账号显示“未分类”且存在对应筛选标签，原有列对齐不回归。
- 执行相关 API/Web 单测、类型检查与目标 E2E；只记录实际执行的命令，不声称未运行的门禁或真实 Casdoor 生产联调已通过。
