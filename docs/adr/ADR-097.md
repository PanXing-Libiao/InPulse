# ADR-097 组织归属对齐 Casdoor 群组

- 状态：Accepted
- 日期：2026-10-26
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-032](ADR-032.md) 的 SSO claim 映射边界与 [ADR-081](ADR-081.md) 的组织归属模型；沿用 ADR-013 的显式事务、ADR-023 的 securityFlow、ADR-029 的统一错误体、ADR-031 的管理员门禁和 ADR-075 的 SSO 首管理员规则
- 修订：2026-10-27 [ADR-098](ADR-098.md) 将直接群组收敛为同一路径族的最深实体群组，并新增“未分类”展示口径；2026-10-27 [ADR-099](ADR-099.md) 允许使用同一 SSO application 的 clientId/clientSecret 通过 HTTP Basic 逐组读取 Casdoor 群组元数据，只保留启用的 Physical 组。其余数据模型、只读边界与安全规则保持不变。

## 1. 背景

Casdoor 用户可同时属于多个群组。群组由 Casdoor organization 命名空间与 group name 组成，支持父子层级；OIDC groups claim 在应用配置 TokenGroupFormat=Path 时返回完整路径，例如 libiaorobot.com/总部/测试部。

InPulse 现有组织模型是一人至多一个组织，并且组织完全由管理员维护，无法表达 Casdoor 的多群组事实。用户明确要求组织归属与 Casdoor 对齐，而不是由 InPulse 自行选择主群组或只取末级名称。

## 2. 决策

### 2.1 Casdoor 是 SSO 用户组织归属的唯一真相源

- 绑定了 sso_subject 的账号，其全部组织成员关系由最近一次成功 SSO 登录的 groups claim 决定。
- 每次成功登录在签发本地 Session 的同一事务内全量对账：删除该用户现有组织成员关系，再按本次 groups claim 插入直接群组成员关系。
- 对账失败不得签发 Session，整个登录事务回滚。
- 本地口令账号继续由管理员维护组织归属；其行为与 ADR-081 保持不变。
- SSO 用户不得通过管理员组织接口手工加入、移出或替换组织。服务端返回 409 ORGANIZATION_SSO_MANAGED。

### 2.2 groups claim 语义

- Casdoor application 必须将 Token format 配置为 JWT-Custom，Token fields 至少包含 Groups，并将 Token group format 配置为 Path。只有该组合会让 id_token 的 groups claim 携带完整群组路径；未使用 JWT-Custom 时 groups 可能缺失，或不是完整路径，前者会导致本系统跳过同步，后者不满足本 ADR 的路径身份与层级约束，生产环境不得以该配置作为对齐依据。
- claim 名为 groups，值必须是字符串数组（允许空数组），每项至少包含 Casdoor owner 与一个 group name，格式为 owner/name 或 owner/parent.../name。
- 路径最多 20 段、总长不超过 512 字符、单个 owner 或名称不超过 100 字符；不得出现空段、前后斜杠或重复项。
- groups 字段缺失表示本次 Token 未提供组织事实：登录成功但不修改组织成员关系，登录审计记录 groupsClaimPresent=false。
- groups 为空数组表示用户没有任何 Casdoor 群组：删除该用户的全部组织成员关系。
- groups 格式非法按 token-invalid 拒绝登录，不写入任何组织或 Session。
- 只接受 Casdoor 返回的原始路径，不裁剪层级、不改写大小写、不把末级名称当作唯一身份。

### 2.3 组织数据模型

- 新增 app.user_organizations：user_id + organization_id 复合主键、source（MANUAL 或 CASDOOR）、created_at；用户与组织删除时级联清理成员关系。
- 把 app.users.organization_id 的现有值一次性迁移为 source=MANUAL 的成员关系，然后删除该列；用户组织归属不再有单一主键真相。
- app.organizations 增加 source、sso_owner、sso_group_path、sso_parent_path、parent_id。
- LOCAL 组织保持原有管理员 CRUD 与名称唯一语义。
- CASDOOR 组织以 (source, sso_owner, sso_group_path) 唯一；不同路径下的同名群组合法，显示名保存为末级路径段。
- 完整路径中的祖先群组按层级自动建立；父组织通过 parent_id 关联，顶层群的 parent_id 为 NULL。Casdoor owner 本身不是群组，不创建为 InPulse 组织。
- 已消失的 Casdoor 群组不根据单次 Token 自动删除组织行；只移除成员关系。Token 只能证明用户 membership，不能证明 Casdoor 群组已被删除。
- CASDOOR 组织不可通过 InPulse 改名或删除；管理员尝试时返回 409 ORGANIZATION_SSO_MANAGED。
- 本地管理员不能把本地账号手工加入 CASDOOR 组织，也不能把 SSO 用户手工加入任何组织。

### 2.4 群组改名与删除

Casdoor Group 的主键是 owner+name，没有不可变数字 ID；完整路径就是同步身份。群组改名或移动在 InPulse 中表现为旧路径成员关系消失、新路径组织与成员关系出现。旧组织行因缺少全量目录快照而不会自动删除，管理员可保留其作为历史配置或后续通过独立清理 ADR 处理。

### 2.5 事务、并发与审计

- 同步只能使用已验签 id_token 中的 groups；ADR-099 起可在事务外使用同一 SSO application 的 Basic 凭据逐组读取 claim 中已出现群组的类型元数据，但不得列取全量目录或使用管理员或跨组织管理凭据。不在数据库事务内发网络请求。
- 同一用户的同步先对用户行取 FOR UPDATE，防止两次并发登录交错插入不同 membership。
- 群组按路径段数、再按字典序固定顺序 upsert；唯一索引兜住并发创建同一路径，冲突后重新读取。
- 组织创建、成员关系变化和 Session 签发使用同一 TransactionContext；任一步失败全部回滚。
- 成功同步写审计 auth.sso_organizations_synced，记录 groupCount、createdOrganizationCount、membershipCount 与 groupsClaimPresent；不记录 Token、Session 或 Secret。
- 组织自动创建与成员同步不产生管理员操作审计；管理员本地操作继续写原有 admin.organization.* 与 admin.user.organizations.assign 审计。

### 2.6 API 与前端

- OrganizationItem 增加 source、groupPath、parentId；listOrganizations 返回 LOCAL 与 CASDOOR 两类组织。
- UserDirectoryItem 与 AdminUserItem 从单一 organizationId/organizationName 改为 organizations 数组。
- AdminUserItem 增加 managedBySso；管理员页面据此禁用 SSO 用户的组织操作。
- getMyOrganizationMembers 返回 organizations 数组与去重后的 items；每个成员携带 organizationIds，保留多群组分类。
- 项目成员选择器按用户所属全部组织展示；整组选择按每个组织展开成员快照，仍受 1～20 人项目经理约束。
- 对 CASDOOR 组织，管理员页面只读展示，不提供改名、删除、加入或移出入口。
- 所有手工本地组织操作仍走现有六条路由、CSRF、If-Match 和数据库级幂等，不新增业务路由。

## 3. 影响

- SSO 用户首次登录后会自动得到 Casdoor 群组对应的组织；多群组不再丢失。
- 迁移只为本地账号保留旧 `users.organization_id` 归属；现有 SSO 账号的旧手工归属不进入新表，避免出现违反来源约束的过渡数据，并由下一次成功 SSO 登录按 groups claim 重建。这是组织真相源切换的预期行为。
- 本地账号仍只能由管理员维护一个手工组织；数据库模型已支持多成员关系，但当前本地管理命令仍以单组织替换语义运行。
- CASDOOR 组织可重复显示末级名称，管理员必须结合 groupPath 识别；本地组织名称唯一规则不受影响。
- 群组层级会进入本地组织数据，但本轮不提供专门的组织树管理页面。

## 4. 非目标

1. 不调用 Casdoor Admin API 拉取全量群组目录，不验证未被任何用户 Token 引用的群组是否存在；ADR-099 的 application Basic 单组元数据读取属于这一边界内的修订例外。
2. 不把 Casdoor isAdmin、roles 或 permissions 映射为 InPulse 权限。
3. 不让组织归属授予项目成员、组长或系统管理员权限。
4. 不为本地账号自动创建多组织选择器。
5. 不提供 Casdoor 群组删除后的本地组织自动清理或回收站。
6. 不改变 SSO 的 state、nonce、PKCE、JWKS、Session 与首管理员规则。

## 5. 验证

- 迁移覆盖旧 users.organization_id 数据迁移、列删除、新表约束、LOCAL/CASDOOR 唯一索引、授权与部署断言。
- 真实 PostgreSQL 集成测试覆盖：首次 SSO 同步自动建组织与层级、多群组、群组变更、空数组清空、缺失 claim 不修改、并发同群组登录、审计、CASDOOR 组织只读、SSO 用户手工组织操作拒绝。
- API 契约、OpenAPI、生成客户端、权限矩阵、测试矩阵与前端单测同步更新。
- 不声称未执行的 CI、Playwright 或生产 SSO 联调已通过。
