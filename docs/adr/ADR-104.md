# ADR-104 全平台项目成员权限三档配置

- 状态：Accepted
- 日期：2026-10-28
- 决策人：项目负责人（用户指示）
- 关联：修订 [ADR-039](ADR-039.md) 的固定例外清单，以及 [ADR-053](ADR-053.md)、[ADR-059](ADR-059.md)、[ADR-062](ADR-062.md)、[ADR-077](ADR-077.md) 中“仅组长或系统管理员”的硬编码项目内门禁；沿用 [ADR-013](ADR-013.md) 的显式事务、[ADR-019](ADR-019.md) 的数据库级幂等、[ADR-023](ADR-023.md) 的写接口策略与 [ADR-029](ADR-029.md) 的统一错误体；新增迁移 `0062_project_member_permissions.sql`

## 1. 背景

项目内权限此前按能力分散硬编码：部分操作对全体活跃成员开放，部分固定为“系统管理员或项目组长”，组长转移、项目删除、模块/功能删除与项目企业微信群都各自维护例外。用户要求把项目成员权限改为系统管理员可统一分配的配置，并明确接受三档口径：

1. 所有成员都有；
2. 只有组长有；
3. 项目成员都没有，只有系统管理员保留。

用户同时确认配置为全平台统一，不按项目单独设置；“查看”和“个人设置”固定开放，不参与配置。

## 2. 决策

### 2.1 配置范围与档位

`app.project_member_permission_settings` 是单行全局配置（固定 `id = 1`），不按项目拆分。11 项能力各取以下三档之一：

| 档位 | 允许身份 | 界面文案 |
|---|---|---|
| `ALL_MEMBERS` | 系统管理员、项目组长、项目普通活跃成员 | 全部成员 |
| `LEADERS_ONLY` | 系统管理员、项目组长 | 仅组长 |
| `ADMINS_ONLY` | 仅系统管理员 | 仅系统管理员 |

不提供“任何人（含系统管理员）都不能操作”的档位。用户所说的“全都没有”解释为“所有项目成员都没有，系统管理员仍保留最终处置权”，以 `ADMINS_ONLY` 表达。

系统管理员始终通过全部 11 项能力；该保证不依赖配置值，也不能被配置收回。

### 2.2 可配置能力与默认值

默认值与引入配置前的运行时行为逐项一致；迁移不放大、不收回既有权限：

| 能力 | 默认档位 | 覆盖范围 |
|---|---|---|
| `projectEdit` | `ALL_MEMBERS` | 编辑项目内容与切换项目状态 |
| `projectMemberManage` | `ALL_MEMBERS` | 添加、移除项目成员 |
| `projectLeaderTransfer` | `LEADERS_ONLY` | 任命或转移项目组长 |
| `projectDelete` | `LEADERS_ONLY` | 物理删除项目 |
| `projectDocumentImport` | `ALL_MEMBERS` | 既有项目内文档导入与项目内 AI 辅助 |
| `moduleFeatureEdit` | `ALL_MEMBERS` | 创建或编辑模块、功能与说明 |
| `moduleFeatureDelete` | `LEADERS_ONLY` | 物理删除模块或功能 |
| `taskEdit` | `ALL_MEMBERS` | 创建、编辑、指派任务及遗留项转任务 |
| `taskLifecycle` | `ALL_MEMBERS` | 任务状态、合并、解除、取消、恢复与删除 |
| `recordWrite` | `ALL_MEMBERS` | 迭代记录、遗留问题、发布与 GitHub 链接写入 |
| `projectWecomGroup` | `LEADERS_ONLY` | 项目微信群绑定、解绑与群消息开关 |

文档导入仍同时受内容操作权限约束：创建模块或功能还需要 `moduleFeatureEdit`，创建任务还需要 `taskEdit`。因此放宽 `projectDocumentImport` 不会绕过实际写入范围。

### 2.3 固定开放与固定管理员

以下能力不进入 11 项配置：

- 固定开放：查看项目、动态、成员与搜索；创建项目与选择初始成员；个人设置、通知偏好与个人企业微信绑定；整项目导入。
- 固定仅系统管理员：迭代记录作废与恢复；系统管理、组织、用户、管理员配置与原始审计。

固定开放不等于跨项目可见：成员仍只能查看自己有权访问的项目与资源；固定管理员仍要求当前有效的完整管理员 Session。

### 2.4 实时判定

每次命令在数据库事务内读取用户状态、`is_admin`、目标项目当前 `ACTIVE` 成员角色与单行配置，不把配置或成员关系缓存进 Session、JWT 或进程内对象。管理员保存后，下一次命令立即按新值判定；已签发 Session 无需刷新或重新登录。

非项目成员、已移除成员和停用用户继续按原有的 404 / 401 语义处理，配置不能把无成员关系的人变成项目成员。配置拒绝返回 403，项目资源不存在与无权访问仍统一返回 404。

### 2.5 数据与权限

迁移 `0062_project_member_permissions.sql`：

1. 建立单行表，固定 `id = 1`，11 个能力列均为 `TEXT + CHECK`，只接受三档枚举；
2. 预插默认行，并用部署断言检查单行、默认值、约束、触发器和角色权限；
3. `app_runtime` 只有 `SELECT` / `UPDATE`，不能新建或删除配置；`app_backup` 只读；
4. 最近保存人使用 ADR-088 身份快照，物理删除用户后仍可展示保存来源。

配置更新使用 `SELECT ... FOR UPDATE`、`If-Match` 版本校验及单条条件 `UPDATE`；版本不符返回 409，不自动覆盖。配置更新与 `SYSTEM` 审计在同一事务内提交。

### 2.6 API、契约与安全

新增两条路由，路由总数 131 → 133：

| operationId | 方法与路径 | 授权与请求约束 |
|---|---|---|
| `getProjectMemberPermissions` | `GET /api/v1/project-member-permissions` | 任意有效登录 Session 可读；无 CSRF、无幂等；响应 `no-store` |
| `updateProjectMemberPermissions` | `PUT /api/v1/project-member-permissions` | 仅完整管理员 Session；同源、同步 CSRF、`If-Match`、数据库级幂等与审计必填 |

写接口摘要覆盖 method、operationId、路径、查询、规范 Content-Type、行为头 `If-Match` 与 JCS 规范化 body；CSRF、Cookie、Authorization 与 `Idempotency-Key` 不进入摘要。重放前重新验证当前管理员 Session、原操作人和单行配置仍存在；管理员被撤权后不得重放旧响应。

请求与响应使用 `ProjectMemberPermissionsUpdateRequest` / `ProjectMemberPermissions` 严格 Schema；所有 11 项必须显式提交。写请求只接受 `application/json`，缺失或非法头部按 422，会话无效按 401，管理员权限不足按 403，版本冲突按 409。

### 2.7 前端

管理员的“成员与设置 → 权限矩阵”可编辑 11 项下拉框并整体保存；普通成员可读取同一配置但只读。固定开放与固定管理员项显示徽标而不提供编辑控件。保存使用生成客户端、同步 CSRF、`If-Match` 与幂等键；失败重试在请求未变化时复用同一幂等键，成功后刷新缓存。409 时提示重新加载，避免静默覆盖。

成员状态筛选的“启用中 / 已停用”分段控件改为固定宽度、两个等宽槽位；数量角标变化不再改变选中滑块宽度或位置。

## 3. 影响

- 管理员可以按业务阶段统一放宽或收紧项目内能力，无需改代码或逐项目配置。
- 旧 ADR 中固定的“仅组长或系统管理员”例外不再直接决定运行时授权；其默认值仍由本 ADR 保留。
- 角色与成员不变量不变：项目必须恰好一名组长、组长不可被直接移除、组长只能转移；配置只决定“谁能调用某能力”，不改变业务约束。
- 文档导入、任务、记录、模块、功能与企微群写入口统一使用同一权限策略；幂等重放也必须重新通过当前配置。
- 权限配置能力本身固定仅系统管理员，不能通过该配置把配置保存权限下放给项目成员。

## 4. 非目标

1. 不支持按项目覆盖，也不支持自定义能力或自定义档位。
2. 不把配置缓存到 Session，不提供离线生效或延迟生效。
3. 不改变项目成员、组长、项目状态、记录版本或审计哈希链不变量。
4. 不把查看、个人设置、整项目导入或记录作废/恢复纳入可配置范围。

## 5. 验证

- 契约：`contract:validate` 与权限矩阵覆盖 133 条路由；生成物无漂移。
- API 单元：三档 × 组长/普通成员、管理员始终放行、非成员、默认值、配置行缺失 fail closed。
- 真实 PostgreSQL + HTTP：管理员保存后立即影响下一次成员管理命令，配置更新与审计同事务，`If-Match` 冲突 409，同 Key 幂等重放，普通成员 PUT 403，匿名 GET 401，非 JSON 400。
- Web：管理员编辑与保存头、普通成员只读、409 提示、固定项徽标，以及成员筛选等宽滑块。
- 本次按用户要求保持精简，不以大量重复用例替代上述关键风险覆盖。
