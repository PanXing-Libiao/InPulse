# ADR-100 Casdoor 管理员批量导入账号与实体组归类

- 状态：Accepted（候选目录范围已由 [ADR-101](ADR-101.md) 修订；预览分类与默认勾选由 [ADR-102](ADR-102.md) 修订）
- 日期：2026-10-27
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：扩展 [ADR-032](ADR-032.md) 的 SSO 身份映射，复用 [ADR-097](ADR-097.md)、[ADR-098](ADR-098.md) 与 [ADR-099](ADR-099.md) 的组织同步口径；沿用 ADR-023、ADR-029、ADR-031、ADR-075 的事务、错误、权限与首管理员规则

## 1. 背景

当前 InPulse 只在用户完成 SSO 登录后 JIT 创建平台账号。管理员无法提前查看 Casdoor 中哪些启用账号尚未进入平台，也无法在不等待逐人登录的情况下建立账号与实体组织归属。

用户要求把 Casdoor 中可登录本应用的账号批量导入，并按 Casdoor 实体组自动建立组织和分类人员。批量操作必须可重复执行，且不能把 Casdoor 凭据、角色或管理员标记带入 InPulse 权限。

## 2. 决策

### 2.1 管理入口与目录范围

- 新增两条系统管理员路由：
  - `GET /api/v1/admin/users/casdoor-import/preview`
  - `POST /api/v1/admin/users/casdoor-import`
- 预览只读、实时从 Casdoor 读取配置组织下启用中的账号，按现有身份映射规则分类为新建、绑定、刷新或跳过；不写用户、组织、审计或幂等记录。
- 确认导入只接收预览后勾选的 Casdoor 稳定账号标识，并在服务端重新读取当前目录；旧预览中的账号消失、停用或改组不得被静默沿用。
- 目录读取范围由非敏感配置 `CASDOOR_IMPORT_ORGANIZATION` 指定；未配置、SSO 关闭或 SSO 配置非法时，路由仍显式存在但返回 503 fail closed。
- 目录读取使用与 SSO 相同的 Casdoor application `clientId` / `clientSecret` HTTP Basic 凭据。凭据只进入服务端请求头，不进入数据库、审计、日志、浏览器或响应。
- 导入候选默认是配置 Casdoor organization 下未停用、未删除的账号。ADR-101 可选按指定 Permission 收窄账号与部门；除此之外，Casdoor roles、permissions、application 授权结果与 `isAdmin` 不参与 InPulse 身份或权限判断。管理员在预览中明确勾选后才导入。

### 2.2 实体组识别与组织归类

- `/api/get-users` 返回的用户 `groups` 保存 `owner/name` 组 ID，不保证是完整层级路径，也不携带 Physical / Virtual 类型。
- 管理员导入在数据库事务外分页读取 `GET /api/get-groups?owner=<organization>`，最多 1000 组；对 owner、name、type、isEnabled、isTopGroup、parentId 做严格校验，并按 parentId 还原完整路径。
- 只把启用中的 `Physical` 直接组写入用户组织成员关系；Virtual 组与停用组忽略。用户引用但当前群组目录已不存在的组视为 Casdoor 陈旧成员引用并跳过该组。
- 组目录读取失败、分页停滞、字段非法、重复组名、父组缺失、父级环或路径非法时整批 fail closed 返回 503，不回退猜测组类型。
- 父级 Physical 组只用于建立组织层级；同一路径族仍按 ADR-098 只保留最深直接组。互不为祖先的多个真实 Physical 组全部保留，不强行截断为一个。若 Casdoor 实际只配置一个实体组，InPulse 也只展示一个。
- 无实体组的账号不建立组织关系，管理员页继续归入“未分类”；“未分类”不是组织行，也不授予任何权限。
- 每次重复导入按 Casdoor 当前实体组全量替换所选用户的 CASDOOR 成员关系。Casdoor 中移除组或移除用户组归属后，下一次勾选该用户导入会清空旧关系。

### 2.3 身份映射与导入语义

- 身份映射沿用 ADR-032：`sso_subject` 命中则刷新；登录名命中且未绑定且邮箱一致时绑定；否则 JIT 新建。邮箱不一致、邮箱已占用或 subject 已绑定其他账号时逐账号跳过。
- 新账号固定 `password_hash=NULL`、`is_admin=false`，不获得任何项目成员关系、项目权限或管理员权限。
- 导入路径显式关闭 ADR-075 首账号管理员授予；即使平台此前没有用户，批量导入也不会产生管理员。
- 目录读取在事务外；所选账号的身份写入、资料刷新、组织创建、成员关系替换与单条批次审计在同一事务内完成。
- 导入不自动停用、删除或重新启用平台账号。已绑定但平台账号被停用或删除的 Casdoor 账号在预览中标记跳过；需要人工恢复或停用平台账号时继续使用 F-03 管理流程。

### 2.4 安全、幂等与审计

- 两条路由都要求当前有效的完整管理员 Session。确认导入还要求同源校验、同步 CSRF Token 与数据库级 `Idempotency-Key`。
- 响应统一 `Cache-Control: no-store`；预览可包含管理员决策所需的脱敏身份、邮箱与实体组路径，但禁止返回 Casdoor 密码、盐、TOTP、Token、Roles、Permissions 或原始响应体。
- 相同 Key、相同摘要与相同契约版本只重放已存计数响应；相同 Key 不同请求体返回 409。重放前重新验证当前管理员身份与 CSRF。
- 每次确认导入只写一条 `admin.user.casdoorImport` 审计，target 为 Casdoor organization，payload 仅包含组织名与创建、绑定、刷新、跳过、组织数与成员关系数，不写登录名、邮箱、Casdoor ID、组路径明细或任何凭据。
- 预览不写审计。目录故障映射为 503；预览后目录缺失所选账号映射为 409；身份冲突逐账号跳过，不让整批回滚。

## 3. 影响

- 路由总数由 129 增至 131；OpenAPI、生成客户端、权限矩阵与测试矩阵同步。
- 管理员可在“成员与角色”页预览 Casdoor 目录，默认全选可导入账号，逐项取消不支持项后一次性导入。
- 首次导入后，用户不必先完成 SSO 登录才出现在平台；其组织归属来自 Casdoor 实体组。
- 不新增数据库迁移，不改变 SSO 登录组织同步、项目成员、项目权限或生产 Secret。

## 4. 非目标

1. 不实现后台定时全量同步、Webhook 或 Casdoor 到 InPulse 的单点主数据镜像。
2. 不把 Casdoor application 的角色 / 权限映射为 InPulse 权限；ADR-101 仅把 Permission 用作管理员导入的候选账号与部门范围过滤，范围外引用一律丢弃，最终仍由管理员勾选。
3. 不自动停用、删除或重新启用平台账号，不传播 Casdoor 的角色、管理员标记或权限。
4. 不把 Virtual 组、停用组或“未分类”落库为真实组织。
5. 不改变 ADR-099 的 SSO 登录逐组元数据校验；全组织群组目录只用于显式管理员导入。

## 5. 验证

- API 单元：目录字段白名单、组织与启用账号过滤、分页上限、群组目录 Physical / Virtual / 停用过滤、parentId 完整路径还原、缺失父组与 malformed 目录 fail closed、身份分类与单事务导入。
- API 集成（真实 PostgreSQL）：预览零写入；新账号无口令且非管理员；同名邮箱一致绑定、邮箱冲突跳过；Physical 组织与成员关系；无实体组不归类；重复导入不重复建号；组移除后清空关系；审计不包含登录名、邮箱或密码哈希。
- API 集成（真实 PostgreSQL + HTTP）：匿名 401、普通成员 403、管理员预览 200 且 `no-store`；缺少幂等键 400；无效 CSRF 拒绝；同 Key 重放不重复建号或写审计；同 Key 不同摘要 409。
- Web 单元：默认全选、逐项取消、冲突原因、实体组末级名称、未分类提示、重新打开刷新目录，以及确认请求同时携带 CSRF 与 Idempotency-Key。
- 静态门禁：`contract:validate` 131 条路由、`contract:drift`、`permissions:check`、类型检查、ESLint、全量相关测试与文档检查。
- 尚未连接真实 Casdoor 执行批量导入 smoke test；不得把本地桩目录或集成测试描述成真实生产联调已通过。
