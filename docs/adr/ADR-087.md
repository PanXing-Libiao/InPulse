# ADR-087 项目动态固化操作人身份快照

- 状态：Accepted
- 日期：2026-10-20
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：修订 [ADR-082](ADR-082.md) 中“删除账号时改写项目动态姓名”的行为，沿用 [ADR-086](ADR-086.md) 的操作人快照口径；新增迁移 `0051_activity_actor_snapshot.sql`

## 1. 背景

项目动态的 `actorName` 原先由读取时关联 `app.users.name` 得到，`activity_projection.actor_id` 又通过 RESTRICT 外键阻止删除用户。账号一旦物理删除，要么删除失败，要么历史动态失去操作人显示名。

用户确认：即使后续完全删除用户，也不得改变项目动态记录，包括操作人姓名和事件当时写入的摘要。审计日志已经在 ADR-086 中采用身份快照；项目动态需要同一类自包含能力。

## 2. 决策

1. `activity_projection` 新增 `actor_snapshot JSONB`。新写入的 `actorId` 非空动态保存 `{ id, name, loginName }`，并校验收到的快照与 `actor_id` 一致。
2. `PostgresActivityWritePort` 在同一 `TransactionContext` 内读取 `app.users` 的身份并随投影写入；`actorId` 为空时写 `NULL`；`actorId` 非空但用户不存在时 fail closed，调用方事务回滚。
3. 迁移 `0051_activity_actor_snapshot.sql` 删除 `activity_projection_actor_id_users_id_fk`。`actor_id` 保留为历史坐标，`actor_snapshot` 的结构由 CHECK 约束兜底。
4. 动态读取优先使用与 `actorId` 匹配的快照姓名；没有快照的迁移前旧行才回退实时用户目录。系统事件继续返回 `null`。
5. 删除用户不再改写 `activity_projection.summary`，并移除 `ActivityWritePort.renameUserReferences`。人员动态摘要中的目标用户姓名在写入时已经固化，后续删除用户、姓名修改或墓碑化都不得改写这些动态。
6. 快照只用于展示，不参与鉴权、成员关系或权限判定。

## 3. 历史数据与边界

- 本迁移不回填旧动态。旧行没有 `actor_snapshot` 时继续按实时用户目录展示；若旧行对应的用户已经物理删除，其操作人姓名无法从该行恢复。
- 已被旧墓碑化流程改写为“删除用户”的历史摘要无法自动还原；本 ADR 只保证新写入和尚未被改写的动态不再受删除影响。
- 项目动态是派生投影，不是审计账本：`actor_snapshot` 不参与 HMAC，也不提供审计级的防篡改证明；审计链仍以 `audit_logs` 为准。
- 本 ADR 只解除项目动态到用户表的外键；用户物理删除及任务、成员、通知等其余用户引用由 [ADR-088](ADR-088.md) 另行实现，本文“不实现用户物理删除”的边界在 ADR-088 后不再适用。
- 项目自身被物理删除时，项目动态仍按 ADR-062 随项目删除；本 ADR 只保证用户删除不会影响项目动态。

## 4. 非目标

1. 不删除、重写或回填历史项目动态。
2. 不改变 Activity API 契约、路由、权限、游标或分类口径。
3. 不把用户身份快照用于授权或实时成员判断。
4. 不改变项目物理删除时对活动投影的清理规则。

## 5. 验证

- 真实 PostgreSQL 集成：USER 动态写入快照并与用户行一致；SYSTEM 动态为 `NULL`；操作人缺失时写入失败。
- 物理删除操作人后，`activity_projection` 行、摘要和快照仍保留，ActivityQueryService 返回快照姓名。
- 迁移断言：用户外键已移除，`actor_snapshot` 列与 CHECK 约束存在且已验证。
- 删除用户集成：`admin.user.delete` 不再产生 `renamedActivityCount`，原动态摘要与快照保持不变。
