# ADR-096 任务、功能与模块改为物理删除

- 状态：Accepted
- 日期：2026-10-23
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：替代 [ADR-058](ADR-058.md) 的任务删除条款与 [ADR-059](ADR-059.md) 的模块/功能删除条款；延续 [ADR-008](ADR-008.md) 的审计只追加、[ADR-062](ADR-062.md) 的项目物理删除与窄口函数模式；[ADR-024](ADR-024.md) 的记录显式作废/恢复生命周期不变

## 1. 背景

ADR-058 与 ADR-059 把任务、功能、模块删除实现为软删除：对象退出读路径，但行、迭代记录、版本和遗留项继续留在数据库中；任务记录还会被自动作废。用户于 2026-10-23 明确要求执行新的删除规则：三类对象都改为物理删除，删除动作本身只保留审计、项目动态和顶层删除事件，不再保留业务快照。

| 删除对象 | 物理删除 | 唯一保留 |
| --- | --- | --- |
| 任务 | 任务本体、状态历史、负责人、影响关系、聚合组关系、外部链接关联，以及该任务的全部迭代记录、版本和遗留项 | 审计记录、项目动态、task.delete 删除事件 |
| 功能 | 功能本体、功能下全部任务、这些任务的全部记录，以及归属于该功能的全部记录、版本、遗留项和链接关联 | 审计记录、项目动态、feature.delete 删除事件；所属模块保留 |
| 模块 | 模块本体、模块下全部功能与任务，以及这些实体的全部迭代记录、版本、遗留项和链接关联 | 审计记录、项目动态、module.delete 删除事件 |

通知历史与 app.external_links 链接主表不属于上述业务对象本体，继续保留；只删除任务/功能/记录侧的关联行。

## 2. 决策

### 2.1 三类删除均为永久删除

- 不提供回收站、还原入口或恢复路由。
- 不保留任务、功能、模块或迭代记录的快照；记录只在用户显式执行作废/恢复生命周期时改变状态，删除级联时直接清理记录及其全部版本。
- 删除成功后再次删除返回 404；幂等重放返回首次成功响应，不重新执行删除。
- 审计与项目动态保留身份快照、对象编号/名称、删除原因、影响面计数和删除时间，足以追溯“谁删了什么”。

### 2.2 级联范围

任务删除：

1. 删除任务行及其状态历史、负责人、任务影响关系、聚合组成员关系、遗留项关联与任务外部链接关联。
2. 删除该任务的全部迭代记录、记录版本、记录遗留项、记录影响关系、记录外部链接关联和对应搜索投影。
3. 删除任务自身搜索投影；app.external_links 主表保留。

功能删除：

1. 删除功能本体、功能下全部任务及其全部下级，以及归属于该功能的记录、版本、遗留项与链接关联。
2. 只删除指向该功能的模块级任务影响关系，不删除模块级任务本身。
3. 所属模块与其他功能保留。

模块删除：

1. 删除模块本体、模块下全部功能与任务，以及这些实体的全部记录、版本、遗留项、影响关系、聚合组关系、链接关联和搜索投影。
2. 模块内不再保留任何记录或任务；普通模块编码随行删除释放。
3. 未分类模块仍由数据库触发器和删除接口双重保护，返回 409 MODULE_UNCLASSIFIED_PROTECTED。

### 2.3 聚合组

- MAIN 任务可以直接删除，不再返回 TASK_GROUP_MAIN_LOCKED。
- 任一活跃聚合组只要包含被删任务，就关闭该组；未被删除的 ACTIVE 成员转为 DETACHED，并写入删除原因和操作者。
- 删除成员后若组内已无成员，则删除组行；否则保留关闭态的组与解除后的历史成员关系。

### 2.4 删除留痕

- 一次模块/功能删除只写一条顶层 module.delete 或 feature.delete；一次任务删除只写一条 task.delete。级联任务或级联功能不逐条伪造删除事件。
- 同事务写一条顶层项目动态：MODULE_DELETED、FEATURE_DELETED 或 TASK_DELETED，并将原实体的历史动态可见性更新为 DELETED。
- 审计、项目动态与通知均不删除。删除不额外发通知，避免通知深链指向已不存在的对象。

### 2.5 数据库窄口

迁移 0059_contract_hard_delete_task_feature_module.sql 新增 SECURITY DEFINER 函数：

- app.hard_delete_task(projectId, taskId, expectedRowVersion, actorId, reason)
- app.hard_delete_feature(projectId, moduleId, featureId, expectedRowVersion, actorId, reason)
- app.hard_delete_module(projectId, moduleId, expectedRowVersion, actorId, reason)
- 内部共享 app.hard_delete_business_scope(...)；该 helper 不授予 app_runtime。

仅三个入口函数授予 app_runtime EXECUTE，PUBLIC 全部回收。业务表 DELETE 权限不直接开放给运行时角色。

锁序固定为项目/父级写前门禁 → 功能 ID 升序 → 任务 ID 升序 → 聚合组 ID 升序 → 迭代记录 ID 升序 → 遗留项 ID 升序。范围内对象先固定到事务临时表，避免级联删除过程中子查询漂移。

### 2.6 API 与前端

- 路由路径不变：deleteTask、deleteModuleTask、deleteFeature、deleteModule。
- 三条删除契约的幂等契约版本升至 2.0.0；响应不再返回 deletedAt/deletedBy/voidedRecordCount，改为返回精确的 deletedRecordCount（功能与模块另含 deletedTaskCount，模块另含 deletedFeatureCount）与 removedLinkCount。
- If-Match 仍为必填版本门禁；CSRF、同源和数据库级幂等口径不变。
- 重放只复核当前认证、原请求资源标识和当前实时角色/父级可写门禁；资源已被物理删除不能使合法重放退化为 404。
- 前端确认文案明确“永久删除、不可恢复、只保留审计与项目动态”；删除成功后失效任务、看板、模块、功能、记录、草稿、遗留项、项目概览、动态、通知、搜索、链接与侧栏计数缓存。

## 3. 影响

- 任务、功能、模块删除后的数据库占用立即释放；对象编码可重新使用。
- 现有软删除存量数据不在本 ADR 中隐式清理；0058 已单独清理历史未分类模块。普通模块/功能/任务若存在历史软删除行，仍按历史兼容读取规则隐藏。
- 记录自身的显式作废与恢复仍保留；只有删除级联时记录才被物理清理。
- 依赖对象历史的页面、搜索、统计、通知深链不再能读取被删除对象，这是预期行为。

## 4. 非目标

1. 不改变项目删除（ADR-062）与账号删除（ADR-088）的范围。
2. 不删除 app.audit_logs、app.activity_projection、app.notifications 或 app.external_links 主表。
3. 不提供导出后删除、回收站、延迟清理或管理员还原。
4. 不为级联删除生成下级 task.delete/feature.delete 事件。
5. 不清理普通模块/功能/任务的历史软删除存量；如需清理必须另立迁移并人工评审。

## 5. 验证

- 迁移 0059 已在本地 PostgreSQL 18.6 实例执行，函数所有权、SECURITY DEFINER、EXECUTE 授权和不删除审计/动态/通知的断言通过。
- 真实 PostgreSQL 删除集成测试覆盖任务、功能、模块的物理范围、记录/版本/遗留项/链接关联清理、审计与动态保留、幂等、并发、权限、版本冲突、聚合组关闭和未分类模块保护；本批 19/19 通过。
- 前端删除确认、响应 fixture 与关联缓存失效单测通过；全 workspace 类型检查通过。
