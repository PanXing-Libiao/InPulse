# ADR-039：移除项目管理员角色，项目内管理权限下放给全体活跃成员

- 状态：Accepted
- 基线固化：2026-09-22
- 修订关系：修订 [ADR-033](ADR-033.md) 的项目内角色模型（取消 `PROJECT_ADMIN`）与「管理操作需 `LEADER`/`PROJECT_ADMIN`」的授权口径；同步修订 [ADR-034](ADR-034.md)、[ADR-035](ADR-035.md) 中「`LEADER` 或 `PROJECT_ADMIN` 可执行」的表述为「任意活跃成员可执行」。ADR-033 的组长身份不变量（创建者默认组长、每项目唯一 ACTIVE 组长、组长成员行不可被普通移除、组长转移仅系统管理员）与 ADR-034 的申请—审批分离、任务/功能归档前置校验、ADR-035 的项目生命周期状态机均保持不变。
- 后续修订：2026-10-28 [ADR-104](ADR-104.md) 将本 ADR 及各后续 ADR 中固定的项目内角色例外改为全平台可配置的三档口径；默认值保持发布行为（成员管理为 `ALL_MEMBERS`，组长转移、项目删除、模块/功能删除与企微群为 `LEADERS_ONLY`）。

## 背景

业务定案：项目内不再需要「项目管理员」这一中间角色，且**所有项目成员都应拥有与原组长同等的管理权限**（成员增删、模块/任务/功能归档与恢复、发起项目归档申请、更改项目状态）。组长作为「项目唯一责任人」的身份标识保留，但其特权只剩「组长成员行不可被普通移除、组长转移/撤销仅系统管理员可为」，管理操作本身不再区分组长与普通成员。

## 决策

1. **角色模型收窄**：`app.project_members.role` 取值由 `MEMBER | PROJECT_ADMIN | LEADER` 收窄为 `MEMBER | LEADER`，`project_members_role_check` 相应收紧。存量 `PROJECT_ADMIN` 成员行在迁移内降级为 `MEMBER`，成员关系与历史保留，不物理删除。`project_members_one_leader` 部分唯一索引与 `project_members_removed_role_check`（`REMOVED` 行只能为 `MEMBER`）不变。
2. **管理权限下放**：以下操作的角色门禁由「系统管理员或本项目 `LEADER`/`PROJECT_ADMIN`」改为「系统管理员或本项目任意 `ACTIVE` 成员」——`listProjectMembers`、`listProjectMemberUnfinishedTasks`、`addProjectMember`、`removeProjectMember`、`archiveModule`、`restoreModule`、`archiveFeature`、`restoreFeature`、`archiveTask`/`restoreTask`/`archiveModuleTask`/`restoreModuleTask`、`requestProjectArchive`、`changeProjectStatus`。非活跃成员仍按资源不存在返回 404；原「普通成员 403」分支取消。
3. **组长保护不变**：`removeProjectMember` 仍不得移除本项目 `LEADER` 成员行（含系统管理员操作），须先由系统管理员转移/撤销组长；防止项目失去唯一责任人。
4. **任命角色路由语义收窄**：`setProjectMemberRole` 路由保留，但请求 `role` 枚举收窄为 `MEMBER | LEADER`，且**仅系统管理员可调用**（用于转移/撤销组长）。组长不再拥有任何任命权（原「组长任命/撤销项目管理员」随 `PROJECT_ADMIN` 一并取消）；普通成员与组长调用返回 403 `PROJECT_MEMBER_ROLE_FORBIDDEN`，非成员 404。审计动作 `project.member.role.set` 与活动类型 `PROJECT_MEMBER_ROLE_CHANGED` 保留。
5. **鉴权实现**：`ProjectRoleGateService.manageRole` 继续实时读取成员行 `role`（不缓存进 Session），返回 `SYSTEM_ADMIN | MEMBER | LEADER | NOT_MEMBER`；管理门禁调用方以「`NOT_MEMBER` → 404，其余 → 放行」判定。`roleSetterRole` 仅当 `SYSTEM_ADMIN` 时放行，`LEADER`/`MEMBER` 归为 `MEMBER`（403），`NOT_MEMBER` 归为 404。
6. **幂等契约版本**：`projectMemberRoleSchema` 枚举、`SetProjectMemberRoleRequest/Response`、`ProjectMemberRecordItem`、`ActiveProjectMemberItem`、`ProjectMemberItem`、`ProjectDetailResponse.currentUserRole`、`ProjectListItem.currentUserRole` 均为重放安全字段，受影响写路由（`setProjectMemberRole`、`addProjectMember`、`removeProjectMember`、`createProject`、`updateProject`、模块/功能/任务归档与恢复、`requestProjectArchive`、`changeProjectStatus`）的 `idempotencyContractVersion` 递增，旧 Key 在新契约下 409。
7. **可见性**：成员列表与项目详情仍下发 `role`（`MEMBER`/`LEADER`）；前端据此显示「组长」徽标与组长转移入口，但**管理操作入口对所有活跃成员开放**，不再按 `LEADER`/`PROJECT_ADMIN` 分流。

## 影响与验证

- 迁移：`0019_drop_project_admin_role.sql`（`UPDATE` 降级 → `DROP`/`ADD` 收紧 `project_members_role_check`；`SET LOCAL ROLE app_owner`，支持从上一正式版本升级与回滚兼容窗口内旧行仍为合法枚举）。
- 契约：`projectMemberRoleSchema = z.enum(["MEMBER","LEADER"])`；受影响路由 summary 与权限矩阵 `conditional` 条目改为「任意活跃成员」；`setProjectMemberRole` 请求枚举与门禁文案更新。OpenAPI、TypeScript 客户端与指纹由生成工具再生成，禁手改。
- 后端：`ProjectManageRole` 类型、`ProjectRoleGateService`、成员管理/模块/功能/任务/归档申请/项目状态服务的 `requireManageRole`/`requireArchiveRole` 与 403 文案、各端口与 HTTP 层的三值内联联合收窄为 `MEMBER | LEADER`。
- 前端：`canManageProjectResources` 改为「系统管理员或任意活跃成员」；成员页移除「项目管理员」徽标与组长任命项目管理员入口，仅保留系统管理员的组长转移；相关错误码文案同步。
- 测试：单元与真实 PostgreSQL 集成需覆盖——普通成员现在可增删成员/归档模块、任务、功能/发起归档申请/改状态（原 403 断言翻转为放行）；组长成员行仍不可被普通移除（409）；组长转移仍仅系统管理员（组长/普通成员 403）；`setProjectMemberRole` 仅接受 `MEMBER`/`LEADER`（`PROJECT_ADMIN` 请求 422）；幂等重放在新契约版本下旧 Key 409。
- 文档：`docs/permissions.md`、`docs/test-matrix.md`、功能设计 §项目内角色、系统设计与技术设计权限表、`AGENTS.md` 第 6 节与 ADR-034 现行规则同步。
