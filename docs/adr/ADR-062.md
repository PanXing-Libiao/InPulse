# ADR-062 项目删除改为物理删除与项目软删除范式下线

> **2026-10-19 修订（[ADR-085](ADR-085.md)）**：项目删除仍为不可逆物理删除，但项目自己的 `PROJECT:<id>` 审计日志与链头不再随项目删除；下文涉及“项目审计链一并清除”“SYSTEM 链是唯一留痕”的历史表述由 ADR-085 取代。

- 状态：Accepted（项目审计链保留口径由 [ADR-085](ADR-085.md) 修订，其余决策继续有效）
- 日期：2026-10-09
- 决策人：项目负责人（用户指示）与开发代理共同确认
- 关联：替代 [ADR-049](ADR-049.md) / [ADR-050](ADR-050.md) / [ADR-051](ADR-051.md) / [ADR-052](ADR-052.md) / [ADR-055](ADR-055.md)；原扩展 [ADR-008](ADR-008.md) 的审计链唯一例外范围（该例外已由 [ADR-085](ADR-085.md) 取代：项目删除不再清空项目自己的链）；沿用 [ADR-019](ADR-019.md) 的数据库级幂等、[ADR-031](ADR-031.md) 的完整管理员 Session、[ADR-033](ADR-033.md) / [ADR-039](ADR-039.md) / [ADR-053](ADR-053.md) 的组长口径；与 [ADR-058](ADR-058.md) / [ADR-059](ADR-059.md) 的任务、模块、功能软删除**互不影响**（本次只改项目层）

## 1. 背景

用户指示（原话）：

> 现在项目是软删除，我想把他改成硬删除，把一切与之相关的都要更改，你先分析然后找我确认

分析后按用户逐项裁决收敛：

> D1② D2① D3② D4提醒操作员，如果还是要删就也一起删除干净 D5管理员看的是「删除项目」 D6按表中来
> 然后还有之前那个软删除30天彻底删除也用不到了

各项含义：**D1②** 幂等重放授权降为 `actorOnly`（项目行物理消失，任何资源级复核都不成立）；**D2①**
删除只对系统管理员可见（只在 SYSTEM 链留一条审计，不写动态、不发通知）；**D3②** 删除后项目编码可
以被新建项目复用；**D4** 前端二次确认提示级联物理删除，用户确认后一次性删干净；**D5** 管理员在审
计页看到的动作名是「删除项目」（`project.delete`）；**D6** 按分析给出的决策表执行。

当前事实：

- [ADR-049](ADR-049.md) 起项目删除是**软删除**（`app.projects.deleted_at` / `deleted_by`）：项目退出
  全部可见范围但数据保留，另配 [ADR-050](ADR-050.md) 的删除记录路由、[ADR-051](ADR-051.md) 的还原与
  彻底删除、[ADR-052](ADR-052.md) 的已删除项目动态、[ADR-055](ADR-055.md) 的保留期自动彻底删除。为
  支撑这条链路，读路径普遍带 `deleted_at IS NULL`，另有 `ProjectAccessQueryPort.isDeletedProject` /
  `listDeletedProjectIds`、动态读取的「已删除项目例外」与 4 条专属路由。
- **物理删除的实现早已存在且经生产级验证**：[ADR-051](ADR-051.md) 的 `app.purge_project(INTEGER)`
  （`SECURITY DEFINER`、固定叶子表到 `app.projects` 的 28 处删除（[ADR-064](ADR-064.md) 起含 `app.document_import_runs`）、断言恰好删除 1 行项目、事务级
  `set_config('app.purge_project_id', …, true)` 为未分类模块保护触发器开窄口）。本 ADR 复用它，只是把
  它从「二次操作」提升为删除的唯一路径。
- 项目已无归档态（[ADR-043](ADR-043.md)），项目编码唯一约束 `projects_code_unique` 在软删除下**不释
  放**编码——被删项目的编码永久占用，与「删除即释放」的直觉不符。
- 软删除范式在任务（[ADR-058](ADR-058.md)）与模块/功能（[ADR-059](ADR-059.md)）上仍然成立，两处各自
  依赖父项目行存在；项目层改为物理删除后，它们的 `deleted_at` 语义与读路径**不需要改动**。
- `deleteProject` 是幂等路由（[ADR-019](ADR-019.md)），原重放授权策略是资源级：重放前复核项目可读
  性。项目行物理删除后该复核必然失败，会把合法重放变成 404。

## 2. 决策

### 2.1 删除语义：不可逆的物理删除

1. `DELETE /api/v1/projects/{projectId}` 由软删除改为**物理删除**：同一事务内清空项目行及其全部下级
   数据（模块、功能、任务、任务聚合组与成员、状态历史、负责人、功能影响、遗留项与转换链接、迭代记
   录的全部版本与关联、外部链接与各层关联行、项目成员关系、通知、动态投影、搜索投影）。项目自己的
   `PROJECT:<id>` 审计链按 [ADR-085](ADR-085.md) 保留，不再清空。
2. 执行走既有窄口 `app.purge_project(INTEGER)`，不逐表授予 `app_runtime` `DELETE`；函数内
   `deleted_at IS NULL` 的存在性守卫与「恰好删除 1 行项目」断言保留为 fail closed。本次把该函数的
   存在性守卫改为按**项目存在性**判定（软删除列已删除），并让函数返回删除行数
   （`modules` / `features` / `tasks` / `change_records` / `audit_logs` / `members` / `total`）供审计载荷使用。
3. 删除**不可逆**：没有还原入口、没有彻底删除的第二步、没有回收站。物理清除只随本次删除发生。

### 2.2 路由收缩：105 → 102

1. **保留**：`DELETE /api/v1/projects/{projectId}`（`deleteProject`）语义改为物理删除；请求体保持
   `noBody`（软删除时代的 `reason` 字段整体删除，请求**不接受** body，携带 body 返回 422）。
2. **删除**：`POST /api/v1/projects/{projectId}/restore`（`restoreProject`）、
   `POST /api/v1/projects/{projectId}/purge`（`purgeProject`）、
   `GET /api/v1/project-deletions`（`listProjectDeletions`）。三者连同其契约 Schema
   （`project-deletion.zod.ts`、`projectPurgeResponseSchema`）、Controller、查询服务与生成客户端产物一
   并移除；调用返回 404。Route Registry 由 105 条降至 **102 条**。
3. 保留 `versionPolicy.ifMatch = required`、`concurrencyPolicy.rowVersion = required`
   （`lockOrder: ["project"]`）、`csrfPolicy: required`、`authPolicy: session`、`auditAction: "project.delete"`。

### 2.3 权限：系统管理员或本项目组长

1. 只有**系统管理员**与**本项目 ACTIVE 组长（LEADER）**可以删除：普通成员与项目管理员
   **403 `PROJECT_DELETE_FORBIDDEN`**；非成员、已移除成员与不存在的项目统一 **404**
   （`PROJECT_NOT_FOUND`，不泄露存在性）。
2. 角色判定沿用 `ProjectRoleGateService.projectDeleterRole`（返回 `SYSTEM_ADMIN` / `LEADER` / `MEMBER` /
   `NOT_MEMBER`），在**同一事务内**读实时成员关系，转移或降级后立即失效。这是 [ADR-039](ADR-039.md)
   授权下放之外的既有例外，本次不变。
3. HTTP 层的 `resolve` 预检对 `deleteProject` **不做**项目可读性复核（项目行随时可能已被删除）；授权
   检查只在首次执行的 `execute` 内进行。
4. 重放只复核**当前认证**（Session 有效、用户未被停用，由
   `IdempotencyHttpService` 在重放前完成），不再复核资源级权限。

### 2.4 审计：SYSTEM 链一条 `project.delete`（D2① / D5；项目链保留口径见 ADR-085）

1. 删除在同一事务内写**恰好一条**审计：`chain = SYSTEM`（`projectId: null`）、`actorType: "USER"`、
   `actorId`、`action: "project.delete"`、`targetType: "PROJECT"`、`targetId: "<projectId>"`、
   `requestId`，载荷含 `code` / `name` / `status` / `rowVersion` / `actorRole` 与 `records`（各表删除行数及 `retainedAuditLogs`）。
   项目自己的 `PROJECT:<id>` 链按 [ADR-085](ADR-085.md) 保留，管理员仍可按项目 ID 或全部链读取；SYSTEM 链的 `project.delete` 仍记录操作事实。
2. **不写**活动投影、**不发**通知、**不写**搜索投影：删除后项目实体已不存在，动态与通知只会成为死
   链（[ADR-035](ADR-035.md) 的通知只能标已读不能作废）。
3. 可见性：审计读取 `getAuditLogs` 仍是 `adminSession`，因此**只有系统管理员**能查到这次删除；普通
   成员在任何列表、动态、搜索、审计入口都看不到它（D2①）。
4. 前端审计页的动作名保持「删除项目」（`ACTION_LABELS["project.delete"]`）；`project.restore` 与
   `project.purge` 标签保留供历史行渲染，但进入已下线动作码候选过滤列表（`RETIRED_ACTION_CODES`）。

### 2.5 幂等：契约版本 2.0.0 与 `actorOnly` 重放授权（D1②）

1. `deleteProject.idempotencyContractVersion` 由 `1.0.0` 升到 **`2.0.0`**（删除语义与重放授权同时变
   化），旧 Key 在新契约下返回 409 `IDEMPOTENCY_CONTRACT_MISMATCH`。
2. `replayAuthorizationPolicy` 由资源级改为 `{ version: "2.0.0", actorOnly: true }`：同 Key、同摘要、
   同契约版本且当前认证有效时直接重放已存的 **204**，不再复核项目可读性或成员关系（两者都已不存在）。
3. 带 `projectId` 的资源级复核**只允许**出现在首次执行的 `execute` 内。`IdempotencyHttpService.run`
   的 `actorId` 回调在**执行与重放两条路径都会运行**，把带任务/项目可读性的复核放进去会让合法重放变
   成 404（[ADR-058](ADR-058.md) 的实测教训），本 ADR 保持同一约束。
4. 失败语义：`If-Match` 陈旧 409 `PROJECT_VERSION_CONFLICT`；缺 `If-Match` 422；缺 CSRF 422；缺
   `Idempotency-Key` 400；未登录 401。全部失败路径**零副作用**（事务整体回滚，项目与其下级数据保
   留）。

### 2.6 项目编码释放（D3②）

1. 物理删除后 `projects_code_unique` 不再占用该编码，新建项目可以复用。这是与软删除的**关键行为差
   异**，需要在测试中显式锁定（同编码先删除、再创建成功）。
2. 不回收、不复用项目 `id`（`BIGSERIAL` 单调递增），历史审计里的 `targetId` 指向的 `id` 不会被新项目
   占用。

### 2.7 前端入口与二次确认（D4）

1. 删除入口仍在「编辑项目」弹窗**页脚最左侧**（`danger-button footer-leading`），只在
   `canDeleteProject(isSystemAdmin, role)` 为真（系统管理员或本项目组长）时渲染。
2. 点击后打开二次确认弹窗（`tone="danger"`、`icon="alert"`），文案明确级联范围与不可逆性：
   「删除不可撤销，会一并物理删除该项目下的全部模块、功能、任务、迭代记录、GitHub 链接、通知、项目
   动态与项目的审计链，项目编码将可以被重新使用。删除后仅在系统审计链留下一条「删除项目」记录，系
   统管理员可在审计日志中查看。」
3. 删除成功后失效项目集合、动态、通知、搜索等缓存并展示成功语；项目从列表消失，不再有「已删除项
   目」筛选、还原与彻底删除按钮、删除记录区块。
4. 用户侧可见的「已删除项目」相关 UI 全部下线：动态页项目筛选的「已删除项目」档位、删除行上的
   「还原项目 / 彻底删除」动作、审计页「已删除项目的审计链入口」、设置页权限说明里的对应条目。

### 2.8 迁移 `0038_project_delete_contract_soft_delete_removal.sql`

1. 先**还原**软删除存量：把 `deleted_at IS NOT NULL` 的项目清空 `deleted_at` / `deleted_by` 并递增
   `row_version`（用户要求「都要更改」；软删除的项目重新可见，不做隐藏丢弃）。
2. `CREATE OR REPLACE FUNCTION app.protect_unclassified_module()`：未分类模块保护的豁免条件由
   `app.purge_project_id` 与 `app.deleted_at` 并存改为只看 `app.purge_project_id`（软删除列已删）。
3. `CREATE OR REPLACE FUNCTION app.purge_project(p_project_id INTEGER)`：存在性守卫改为项目行存在
   判定；返回各表删除行数；`REVOKE ALL … FROM PUBLIC` + `GRANT EXECUTE … TO app_runtime`。
4. `DROP` 软删除面：约束 `projects_deleted_state_check`、外键 `projects_deleted_by_users_id_fk`、列
   `deleted_by` 与 `deleted_at`。
5. 文件名含 `_contract_` 以通过 `database/src/migrations.ts` 的破坏性 DDL 守卫；历史迁移
   `0000`–`0037` 不改写。

### 2.9 读侧收敛

`deleted_at IS NULL` 一类的软删除过滤在项目层整体移除：项目列表/详情、项目成员、统计与完成率、动态
读取（`ActivityQueryService` 的「已删除项目例外」改为纯 `assertProjectAccess`）、搜索授权范围、任务与
记录的父项目校验、外部链接聚合、`ProjectsWritePort.countOpenTasks` 的父项目条件等。任务与模块/功能层
的 `t.deleted_at` / `m.deleted_at` / `f.deleted_at`（[ADR-058](ADR-058.md) /
[ADR-059](ADR-059.md)）**保持不动**。

### 2.10 ADR-055 保留期自动彻底删除一并取消

1. `ProjectAutoPurgeService` / `ProjectAutoPurgeScheduler` 与 `PROJECT_AUTO_PURGE_*` 环境变量整体删除：
   删除已经是物理的，不存在「30 天后彻底删除」的第二阶段。
2. 无数据库后台任务、无 SYSTEM 链的 `project.purge`（`trigger = AUTO_RETENTION`）；手工路径的
   `project.purge` 也随 [ADR-051](ADR-051.md) 下线一并消失。

## 3. 影响与代价

- **不可逆性**：用户失去「先删除再观察」的回退余地。这是用户明确选择（D4「提醒操作员，如果还是要删
  就也一起删除干净」），由二次确认弹窗的显式文案承担告知义务。
- **级联范围大**：一次删除会物理清除 25 张项目作用域表的业务数据；项目审计链按 [ADR-085](ADR-085.md)
  保留，SYSTEM 链另有一条 `project.delete`（含各表行数）。这是本 ADR 的核心权衡。
- **幂等重放不再有资源级保证**：同 Key 重放只看认证。由于删除结果不可变且 `projectId` 不复用，重放
  返回已存 204 不构成越权。
- **`app.purge_project` 的权限面扩大**：它从「管理员二次确认后的彻底删除」变成唯一删除路径，但窄口
  设计（`SECURITY DEFINER` + 固定删除顺序 + 单行断言）未变。
- **编码复用带来的历史歧义**：审计里的 `targetId`（项目 id）不复用，但 `code` 可能出现在新项目上；
  审计载荷同时记录 `code` 与 `name`，可人工区分。

## 4. 非目标

1. **不改**任务删除（[ADR-058](ADR-058.md)）与模块/功能删除（[ADR-059](ADR-059.md)）的软删除语义、级联
   范围与路由；它们的 `deleted_at` / `deleted_by` 列与读路径过滤保持原样。
2. **不提供**项目还原、回收站、导出后删除或删除前自动备份。
3. **不新增**删除预览路由：确认弹窗只复用编辑弹窗已加载的项目详情，不展示下级行数预估。
4. **不改**项目状态三态（[ADR-043](ADR-043.md)）、归档态下线、维护中自动回到进行中的口径
   （[ADR-056](ADR-056.md) / [ADR-057](ADR-057.md)）。
5. **不改**审计链哈希算法与 SYSTEM 链只追加语义（[ADR-008](ADR-008.md)）；项目链保留口径由
   [ADR-085](ADR-085.md) 修订，不再存在“项目链随项目删除”的例外。
