# ADR-032：接入立镖 Casdoor OIDC 单点登录（SSO）

- 状态：Accepted（2026-09-18 由 [ADR-036](ADR-036.md) 修订决策 7 的前端入口：`/login` 默认展示本地口令表单，统一身份认证改为并列入口，再经 [ADR-080](ADR-080.md) 恢复为「默认直达 SSO、本地口令表单退居隐藏应急入口」；决策 5 的 JIT 默认权限由 [ADR-075](ADR-075.md) 修订（空库首个账号自动授予管理员，其余照旧）；claim 白名单另由 [ADR-097](ADR-097.md) 修订为增加 groups，其余决策不变）
- 决策日期：2026-09-15
> 2026-10-19 更新：决策 11 中的 `force-logout` 能力底层已由 [ADR-083](ADR-083.md) 移除；离职回收仍可使用 `disable`，不再提供管理员强制退出接口。
- 接受依据：用户 2026-09-15 确认按公司统一身份方案接入 Casdoor OIDC，并确认默认策略：SSO 首次登录自动开通账号（默认非管理员、无任何项目权限）、本地会话 30 分钟、保留 `/login?local=1` 本地口令入口供管理员应急。同日已用测试环境（`authtest.libiaorobot.com`）完成端到端冒烟：Authorization Code + PKCE(S256) 换取 token 成功、id_token 以 RS256（kid=`cert-built-in`）通过 JWKS 验签、claims 含 `name`/`displayName`/`email`/`sub`、`aud` 等于 Client ID。
- 替代范围：修订 ADR-031 的登录语义（口令登录不再是唯一认证入口）；修订 ADR-023 的一次性安全流程 allowlist（3 条扩为 5 条）；修订《技术设计》4.2 状态码语义集合（新增 302 重定向）与《系统设计》认证机制相关条目。其余安全与数据基线不变。

## 背景

公司统一身份系统「立镖单点登录」基于开源 Casdoor 构建（正式环境 `auth.libiaorobot.com`，测试环境 `authtest.libiaorobot.com`），要求各应用以**标准 OIDC 协议**接入（明确不使用 Casdoor SDK），仅允许 Authorization Code 模式，凭 Client ID 与 Client Secret 对接；用户字段映射为 `Name`（登录名）、`DisplayName`（姓名）、`Email`（企业邮箱）；应用需自行管理会话超时（内部系统建议 30 分钟）并提供隐藏的本地口令入口供超级管理员应急；员工离职后公司脚本将调用应用提供的「禁用/删除用户」接口完成闭环。

InPulse 当前只有口令登录（ADR-031 后无第二因素），管理员由 `users.is_admin` 本地判定。接入 SSO 后普通员工不再使用本地口令；本地口令入口仅在隐藏路径保留给管理员。SSO 只负责「证明你是谁」，业务权限仍由本地项目成员关系与 `is_admin` 决定。

## 决策

1. **OIDC 角色与流程**：InPulse API 作为机密 Relying Party，采用标准 Authorization Code + PKCE(S256)；授权端点、token 端点与 JWKS 一律从 issuer 的 `/.well-known/openid-configuration` 发现，禁止硬编码路径。`client_secret` 只存在于服务端，换取 token 为服务端到服务端调用（HTTP 请求一律在数据库事务之外执行）。
2. **新增两条认证路由**（均为 GET 且登记 `securityFlow`）：`/auth/sso/start` 生成 state、nonce 与 PKCE verifier 并 302 到授权端点；`/auth/sso/callback` 校验并一次性消费 state，服务端换取 token、验签并校验 id_token（RS256、iss、aud、exp/nbf、nonce），完成用户映射后签发本地会话并 302 回应用。ADR-023 allowlist 扩为 `issueCsrfToken`、`login`、`logout`、`startSsoLogin`、`completeSsoLogin` 五条，且必须且只能声明 `securityFlow`。
3. **契约机制扩展（302 重定向型路由）**：状态码语义集合新增 `302`（重定向）；`noBody` 允许用于 `302`（原仅 `204`）；无 2xx 声明的路由不参与生成客户端（浏览器导航型），OpenAPI 照常生成 302 响应与 `Location` 语义说明。该扩展只服务浏览器导航的 OIDC 端点，业务接口不得使用 302。
4. **一次性登录材料**：新表 `app.sso_login_attempts` 保存 state/nonce/code_verifier 的 Hash（复用会话 HMAC keyring 的哈希策略）、`return_to`、`expires_at`（10 分钟）与一次性消费时间；过期数据由既有 Session 清理机制分批清除。state 在换取 token 前以条件更新一次性消费；消费失败或 token 交换失败时用户须重新发起 start。start 同时下发短期 `__Host-sso-state` HttpOnly Cookie 保存 state，回调必须同时匹配 URL 的 `state` 与 Cookie（缺一即拒绝），防止把他人完成的授权响应塞进受害者浏览器（login CSRF 与会话固定）。
5. **用户映射与开通（JIT）**：`users.sso_subject`（唯一、可空）保存 Casdoor 的 `sub`；`login_name` 取 `Name`（沿用既有规范化唯一索引语义）、`name` 取 `DisplayName`、`email` 取 `Email` 并在每次登录时同步展示字段。查找顺序：按 `sso_subject` 命中直接登录；未命中时按 `login_name` 命中且该账号未绑定任何 subject 则**仅在邮箱一致时**自动绑定（防同名接管），否则拒绝并审计；两者均未命中则自动开通新账号（`is_admin=false`；若平台此前没有任何账号，本次开通按 [ADR-075](ADR-075.md) 自动授予系统管理员；无项目成员关系、无本地口令）。**Casdoor 的 `isAdmin` 等其余 claims 一律不得用于 InPulse 权限判定**；id_token 只用于本次认证，不落库、不写日志；除上述四类身份字段外，按 [ADR-097](ADR-097.md) 另提取已验签 id_token 的 groups。groups 缺失时登录成功但不修改组织关系，格式非法时按 token-invalid 拒绝登录；组织归属与对账规则由 ADR-097 定义。
6. **本地会话**：SSO 成功签发的会话与口令登录**同构**（同一 `user_sessions` 机制、`auth_state=AUTHENTICATED`、`__Host-session` Cookie、CSRF 轮换），不依赖 id_token 存续。本地会话有效期改为 30 分钟（自签发起，配置项默认 1800 秒，含口令登录），不引入逐请求滑动写放大（空闲时长取值已经 [ADR-038](ADR-038.md) 修订为默认 2 小时/7200 秒）；会话过期后前端在 401 时静默重走 SSO（SSO Cookie 7 天内无感），口令入口管理员需重新输入口令。
7. **前端入口**：`/login` 默认自动跳 `/auth/sso/start`（携带 `return_to`，服务端校验为站内相对路径，防开放重定向）；`/login?local=1` 显示既有本地口令表单；SSO 未配置时 start 302 回 `/login?local=1&sso=disabled`，登录页展示本地表单与说明。SSO 回调失败时 302 回 `/login?sso_error=<code>` 展示可读错误。
8. **数据库（迁移 0013，expand 思路）**：`users` 新增 `sso_subject`（唯一索引 `WHERE sso_subject IS NOT NULL`）；`password_hash` 改为可空（`users_password_hash_check` 同步改为 `NULL OR 前缀校验`）；新增 `sso_login_attempts` 表；历史迁移 0000–0012 不动，不删除任何既有列。
9. **配置与 Secret**：`SSO_ENABLED`（未设置视为关闭，本地与 CI 默认关闭，不影响既有口令 E2E）、`SSO_ISSUER`、`SSO_CLIENT_ID`、`SSO_CLIENT_SECRET_FILE`（文件路径模式；生产指向 `/run/secrets/*`，本地指向 `.data/sso/client-secret.txt`）；缺失、空值或不可读一律 fail closed（SSO 不可用并回落本地入口，不允许明文环境变量兜底）。
10. **审计**：新增 `auth.sso_login`（成功）、`auth.sso_login_failed`（含原因分类，不含任何 token/secret）、`auth.sso_account_provisioned`、`auth.sso_account_linked` 事件；沿用审计哈希链与同事务语义。
11. **离职回收**：本期复用既有 `POST /admin/users/{userId}/disable` 与 `force-logout` 作为能力底座；面向公司自动化脚本的服务间调用方式（凭据形式、按 Name/Email 定位用户）待 IT 对接确认后另行补充 ADR 或设计修订，不阻塞本 ADR 落地。

## 非目标（本期不做）

- Back-Channel Logout 即时踢线（已确认 Casdoor 支持 `backchannel_logout_supported=true`，列为二期增强）。
- 从 Casdoor 同步任何权限（管理员、项目成员、角色）；InPulse 权限体系不引入外部输入。
- 移除口令登录（`login` 路由保留，作为隐藏的管理员应急入口）。
- 把 id_token 用作会话凭证或在前端保存。

## 影响与验证

- 契约与生成物：Route Registry 由 95 条增至 97 条；`securityFlow` allowlist 与 `docs/permissions.md` 认证安全流程矩阵必须精确等于 5 条；OpenAPI 与生成客户端随 `contract:generate` 更新，`contract:drift` 与 `permissions:check` 必须通过；`controller-bindings` 静态扫描须识别新 Controller。
- 数据：迁移支持从上一正式版本升级（加列可空、加表），旧代码对新列无感知，可在同一窗口内互退；演示种子与备份无需变更。
- 认证与安全验证（真实 PostgreSQL 集成测试 + stub IdP）：成功登录、JIT 开通、既有绑定登录、邮箱不一致的同名拒绝、state 重放/过期/并发消费、nonce 不匹配、签名错误、iss/aud 错误、禁用用户拒绝、`return_to` 开放重定向拒绝、限流生效；浏览器 E2E：SSO 全流程（stub IdP）、本地隐藏入口、`sso=disabled` 回落。
- 文档同步：功能设计（登录与账号章节）、系统设计（认证机制）、技术设计（4.2 状态码、认证流程）、权限矩阵、测试矩阵、`AGENTS.md` 与 `README.md` 的命令/事实段落。
- 真环境联调（测试环境已完成冒烟）：正式联调在接入部署后按上线清单执行，正式环境凭据与 Redirect URL 由上线流程登记。
